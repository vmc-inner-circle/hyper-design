# Brief

- PRD: `prd/family-trip.md` (원본은 고치지 않음)
- 모드: 제출 (답 4턴 상한, 개입 5회)

## PRD 분석

- 사용자 역할: 일정을 짜는 자녀(계획하는 사람) / 동행하는 부모(확인만 하는 사람) / 그 밖의 동행 가족(다른 자녀·배우자·손주 — 어느 쪽인지 PRD에 없음)
- 역할별 핵심 과업:
  - 짜는 자녀 — 날짜별 이동·숙박·활동 적기, 순서 바꾸기·고치기, 항목마다 확정/후보 표시, 부모에게 무엇을 언제 보일지 정하기, 바뀐 것 알리기
  - 부모 — 묻지 않고 여행 큰 흐름(언제·어디로) 보기, 바뀐 것 알기, 내 준비물·있어야 할 곳 확인 (적은 단계로)
  - 동행 가족 — 내가 준비할 것, 언제 어디에 있어야 하는지 확인
- 화면 목록 초안: 여행 목록/홈 · 여행 만들기(날짜·구성원 초대) · 일정 편집(날짜별, 확정/후보, 순서 바꾸기) · 항목 추가·수정 · 부모용 흐름 보기(한 화면) · 바뀐 것 모아보기 · 할 일·준비물 · 구성원/초대
- PRD가 판단을 넘긴 지점: 역할별로 무엇을 다르게 보여줄지(§4-3) / 알림이 부담되지 않는 전달 방식(§4-5) / 갈등을 푸는 구조(§5)
- 빈 구멍:
  - 후보 항목을 부모에게 아예 숨기는지, 표시해서 보이는지 (§2-1 ↔ §4-2·§2-2)
  - "확인만 하는 사람"이 부모만인지, 일정을 짜지 않는 다른 자녀·배우자도 포함인지 (§4-3 ↔ §2-3 "가족 구성원")
  - 편집하는 사람이 한 명인지 여럿인지 / 손주가 앱을 쓰는지
  - 무엇을 "변경"으로 보고 알리는지 (후보 수정도 알리는지, 확정 변경만인지)
  - 예약 확인서 같은 첨부가 필요한지 (PRD에 없음 → 만들지 않음)

## 가정 로그

- 기기: 부모·동행 가족 화면은 모두 모바일 (§3 "스마트폰에서 여러 단계 조작 답답"). 짜는 자녀의 일정 편집은 두세 달 동안 수시로 고치고 순서를 바꾸는 일이라 PC 추가 후보 — 생성 단계에서 screen-generation.md 신호로 정함 (묻지 않음)
- 손주: 앱 사용자로 보지 않고 구성원 이름으로만 둠 (어린 손주가 많고, 화면 구조가 바뀌지 않음) — Q2 답이 형제·배우자를 넓게 포함하면 다시 봄
- 예약 확인서 첨부·지도·경비 정산: PRD에 없음 → 만들지 않음
- 색·간격·폰트·아이콘·더미 데이터·빈 상태: AI가 정함 (SKILL §1)
- 소식 보내는 시각 저녁 8시 (J4 가정) — 하루 일을 마친 뒤, 부모 세대가 휴대폰을 보는 시간으로 가정
- 짜는 사람 일정 화면의 "오늘 저녁 소식" 미리 보기 (J4 가정) — 자동으로 가는 것이 무엇인지 짜는 사람이 알 수 있게. 보내기 버튼은 없음
- 준비물은 짜는 사람만 더함 (J3 가정) — 확인하는 사람은 읽기만 (여러 단계 조작 줄임)
- 짜는 사람이 여럿일 수 있음 (J2 가정) — 가족 화면에서 역할을 바꿈, 화면 구조는 같음
- 여행 만들기·가입 화면은 만들지 않음 — 핵심 갈등과 무관, 초대 링크로 들어온 뒤부터 그림
- 더미 데이터: 11월 12일(목)~15일(일) 제주 3박 4일, 가족 6명 (엄마 박정희·아빠 김영수·짜는 딸 김지은·아들 김준호·며느리 이수진·손주 서윤)
