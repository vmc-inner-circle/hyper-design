## 불변 원칙

1. **사용자에게는 렌더링된 시안을 보여주고 고르게만 한다.** 전문 용어(타이포, 레이아웃, 위계, 그리드, 톤앤매너, 컴포넌트, IA, UX, UI, 플로우, 와이어프레임, 팔레트, 폰트명) 금지. 답은 글자 하나(`A`)로 끝나게.
2. **화면 구성·흐름은 묻지 않고 스스로 정한다.** 정한 것은 `out/brief.md` 가정 로그에 남긴다.
3. **이해가 먼저, 예쁨은 나중.** 화면마다 핵심 메시지 한 문장 + 주요 행동 1개. 설명 문구로 이해시키는 UI는 실패다.
4. **덜어낸다.** 모든 섹션은 "누구를 위해, 언제 보는가"를 가져야 하고, 없으면 지운다. 같은 목적의 버튼을 두 번 두지 않는다. 데이터가 빈약한 통계·인사이트 칸, 장식용 이모지·일러스트 금지.
5. **뻔한 게 이긴다.** 토스·당근 수준의 국내 대중 앱 패턴. 독창적 레이아웃 금지. 한 화면에 한 가지 일.
6. **절제된 비주얼 — 토큰 밖 값 금지.**
   - 색: 포인트 컬러 **1개**(+ 그 옅은 틴트 1개). 오류 표시도 포인트 컬러 계열이나 무채색으로 — 빨강·파랑을 따로 추가하지 않는다. 무채색은 흰색 포함 **5단계**만(`--gray-0`~`--gray-4`). 틴트도 회색 단계로 세므로 합쳐 6개 이하.
   - **대비**: 글자색은 배경 대비 4.5:1 이상. 보조 글자 회색도 흰 배경에서 4.5:1 이상(#6B6B6B보다 밝으면 안 됨). 포인트 컬러는 **흰 글자와 4.5:1 이상**이 되도록 충분히 진하게 잡고, 포인트 컬러를 글자로 쓸 때도 4.5:1. 비활성·요일 라벨 등 "흐린 글자"도 예외 없음.
   - 글자: 크기 ≤ 6종, 굵기 400/600/700 3종, 패밀리 Pretendard 1종. `button, input, select, textarea { font: inherit; }` 리셋 필수.
   - 여백: `--space-*`(4·8·12·16·20·24·32·40) 토큰만. 1px·2px·음수 margin 금지(테두리는 border로).
   - radius 3종(작게·중간·원형), 그림자 1종(바텀시트용).
   - 선택 상태(칩·탭·세그먼트)는 **채워진 포인트 컬러를 쓰지 않는다** — 테두리+틴트 배경+포인트 글자색. 채워진 포인트 컬러는 화면의 주요 버튼 1개 전용.
   - 모든 눌리는 요소(칩·탭·세그먼트·목록행·아이콘 버튼)는 **높이 44px 이상**.
7. **AI 티 금지.** 모든 것을 둥근 카드로 감싸지 않는다(목록은 구분선, 카드는 정말 묶음일 때만). 카드 안에 카드 금지. 그라데이션·이모지 아이콘·텍스트 그라데이션 금지. 아이콘은 인라인 SVG(선 1.75px, 24px) 또는 텍스트 라벨.

3. 화면 빌드: 서브에이전트 **4개 병렬**(한 메시지에), 화면을 3~4개씩 나눠 맡긴다. 각 에이전트에 전달: 불변 원칙 전문, `out/brief.md`, `out/tokens.css` 경로, 맡은 화면 목록(id·제목·role·핵심 메시지·주요 행동·섹션·links·states), 화면 규칙:
   - 파일: `out/screens/<id>.html`, 상태 변형은 `out/screens/<id>--<state>.html`
   - `<link rel="stylesheet" href="../tokens.css">` 사용, 화면 전용 스타일은 최소한. 새 색·새 폰트 크기 금지.
   - `<h1>`은 정확히 1개(앱바 제목 또는 화면 제목). 채워진 포인트 컬러 버튼은 화면당 최대 1개.
   - 터치 영역 44px 이상. 본문 15px 이상, 최소 글자 13px.
   - **`viewer` 화면은 모든 글자 17px 이상**(보조 정보 포함). 보기만 하는 사람은 글자 크기에 민감하다.
   - 입력칸 아래 도움말 문장·`help`/`tooltip` 클래스 금지 — 설명이 필요하면 구조를 바꾼다.
   - 이동하는 요소는 `<a href="<id>.html">`로 실제 연결(links의 화면으로). 탭바도 링크.
   - 더미 데이터는 PRD 맥락의 현실적인 한국어(실제 이름·지명·날짜·시간). "텍스트", "제목", lorem, TODO, "여행 1" 금지. 이미지가 필요하면 단색 블록+라벨이나 SVG로, 외부 이미지 URL 금지.
   - `title` 속성, 물음표 도움말 아이콘, 툴팁 금지.
   - 375px 폭에서 가로 스크롤이 생기면 안 된다.
   - 하단 고정 버튼·탭바가 있으면 본문 아래 여백을 그 높이만큼 둔다. **필수 입력은 모두 고정 버튼 위에서 보여야** 한다(812px 높이 기준).
   - 헤드라인·배너·섹션 제목이 같은 말을 반복하지 않는다. 탭·필터 아래에는 그 범주의 항목만.
   - 앞 단계에서 이미 정한 값을 다음 단계에서 다시 고르게 하지 않는다.
   - 한 화면에서 받는 입력이 3종류 이상이면 단계를 나눈다(한 화면 한 가지 일).
   - 항목이 20개를 넘을 수 있는 목록에서 고르는 화면은 맨 위에 검색 입력.
   - 경고·추천·주요 버튼이 서로 반대 말을 하지 않는다(경고가 뜬 선택지를 추천하지 않는다).
   - `out/brief.md`의 시나리오 데이터 표만 사용한다. 링크로 이어지는 화면은 같은 항목을 이어서 보여준다.
   - 선택 상태는 전부 `tokens.css`의 `.is-selected` 한 가지 스타일을 쓴다(칩·체크·라디오·세그먼트 공통). 화면에서 선택 스타일을 새로 만들지 않는다. 포인트 컬러를 분류 태그 색으로 쓰지 않는다(분류는 무채색 배지).
   - 서버로 보내는 버튼(보내기·확정·저장·답하기)은 **누른 뒤의 결과가 화면으로 이어져야** 한다: 결과 화면으로 링크하거나, 결과가 반영된 화면에 짧은 완료 표시(상단 한 줄). 보내는 동안은 `tokens.css`의 `.btn.is-loading`(버튼 안 스피너) — 별도 로딩 화면은 만들지 않는다.
