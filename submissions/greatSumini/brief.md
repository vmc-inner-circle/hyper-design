# 브리프 — 가족여행 계획 앱 「함께가요」

## 한 줄 해법
자녀의 **작업 노트(후보 가득, 수시로 고침)** 와 부모의 **여행 안내판(확정된 큰 흐름 + 모일 시간·장소)** 을 같은 데이터로 두 판으로 나눈다. 후보는 부모에게 "정하는 중 · 언제까지 정해요" 한 줄로만 접혀 보이고, 변경 알림은 **확정 항목이 바뀔 때만, 자녀가 모아서 한 번에** 보낸다. 부모는 묻는 대신 "궁금해요" 한 번 누르기.

## 역할
| 역할 | 누구 | 화면 차이 |
|---|---|---|
| 계획자 (planner) | 김지은(딸, 34) | 후보·확정 모두 보고 편집, 순서 바꾸기, 부모님 판 미리보기, 변경 소식 묶어 보내기, 할 일 나누기 |
| 보는 사람 (viewer) | 김영호(아버지, 66) · 박정숙(어머니, 63) | 확정 항목만 크게, 후보는 "정하는 중" 한 줄, 다음 모일 곳이 홈 맨 위, 글자 17px 이상, 한 번 누르면 끝나는 조작만 |
| 함께 가는 가족 (shared) | 김민수(아들, 31), 위 모두 | 내 할 일·준비물, 모이는 곳 |

### 섹션(대상·시점)
- parent-home: ①다음 모일 곳 헤드라인(부모, 앱 열 때마다) ②새 소식 1줄(부모, 변경 보냈을 때만) ③날짜별 큰 흐름 4줄(부모, 궁금할 때) ④내 준비물 남은 수(부모, 출발 1~2주 전)
- planner-home: ①알릴 변경 N건(지은, 편집 후) ②D-51 + 날짜 4줄(확정/후보 수) ③할 일 남은 수 ④가족(누가 들어왔는지·읽음)
- parent-day: 확정 항목 시간·장소 크게 / 후보는 "정하는 중 · 11월 10일까지" 한 줄로 접기 / 궁금해요 버튼
- notify-compose: 보낼 소식(확정 변경, 체크됨) / 알리지 않는 수정(후보, 회색, 접힘) / 받는 사람
- planner-day: 날짜 칩(20·21·22·23) / 시간순 목록(끌기 손잡이, 확정·후보 배지) / 부모님 판 미리보기 링크

## 상태 파생
- planner-day: list_first_use → `empty` (날짜에 아직 아무것도 없을 때: "일정 추가" 하나)
- tasks-all: list_first_use → `empty`
- item-edit: form → `error` (시간 비움)
- my-tasks: shared인데 부모가 봄 — 편집 요소 자체가 체크뿐이라 readonly 아님 → default만
- 나머지 default 하나

## PRD 커버리지
- F1 일정 작성·수정 → planner-day(끌기 손잡이로 순서 바꾸기, 날짜 칩), item-edit(이름·시간 고치기)
- F2 확정 여부 → planner-day·item-edit의 확정/후보 배지·세그먼트, parent-day에서 후보는 '정하는 중'으로 접힘
- F3 역할별 다르게 → share-preview(계획자가 부모 판을 그대로 봄), parent-home/parent-day(확정만, 큰 글자, 다음 모일 곳 우선) vs planner-home(알릴 변경 수, 후보 수)
- F4 할 일·준비물 → tasks-all(누가 무엇), my-tasks(내 몫만)
- F5 변경 전달, 알림 부담 ↓ → notify-compose(확정 변경만 자동 선별, 후보 수정 제외, 모아서 한 번), parent-news(바뀐 전·후 한 장), parent-home 새 소식 1줄
- US1 후보를 편하게, 오해 걱정 없이 → planner-day 후보 배지 + share-preview "부모님께는 정하는 중으로 보여요" + notify-compose "후보 수정은 알리지 않아요"
- US2 매번 묻지 않고 큰 흐름 → parent-home 날짜 4줄 흐름, parent-day "정하는 중 · 11월 10일까지"(언제 정해질지 알면 안 물음), 궁금해요 한 번 누르기
- US3 무엇을 준비하고 언제 어디에 → parent-home 헤드라인(모일 시간·장소), meet-point, my-tasks
- S1 두세 달 전부터 여러 번 바뀜 → 변경을 쌓아 두었다 묶어서 보내는 notify-compose, 읽음 확인 notify-sent
- S2 4~6명, 손주 포함 → invite(역할 선택), 계정 없는 손주 하윤은 인원·카시트 할 일로만 등장
- S3 3박 4일~7박 8일 → 날짜 칩 가로 나열, parent-home 날짜별 한 줄
- S4 예약 끝난 항목 vs 계속 바뀌는 현지 일정 → 항공·숙소·렌터카 = 확정 배지, 현지 일정 = 후보
- S5 부모는 여러 단계 조작이 답답 → join 버튼 하나로 합류(가입 없이 링크), 부모 화면 모든 행동이 한 번 누르기, 17px 이상
- S6 자잘한 할 일 → tasks-all 담당자 지정, my-tasks
- 조건 두 세대 → planner/viewer 두 흐름 모두 화면 존재

## 역할별 진입 흐름
- 지은: planner-home → invite(부모님 초대) → planner-day → item-edit → share-preview → notify-compose → notify-sent
- 부모: 카카오톡 링크 → join → parent-home → parent-day / parent-news / meet-point / my-tasks

## 가정 로그
- 여행 만들기(목적지·날짜 입력) 화면은 생략: 이미 만들어진 여행을 기준으로 핵심 갈등만 보여준다.
- 할 일 추가 입력 화면 생략: tasks-all 안 한 줄 입력으로 대체. 모이는 곳 입력은 item-edit와 같은 방식이라 생략(항공 항목에 딸린 값).
- 부모 가입 절차 없음: 초대 링크 = 보기 권한. 비밀번호·인증 단계 제거.
- "궁금해요"는 질문 입력이 아니라 한 번 누르기 → 지은에게 "아버지가 둘째 날을 궁금해하세요" 알림. 글 쓰는 부담 제거.
- 알림 자동 규칙: 확정 항목 변경만 대상, 후보 추가·수정·순서 변경은 대상 아님. 지은이 모아서 보낸다(원할 때 매주 금요일 저녁 자동 묶음).
- 민수는 계획을 같이 짜지 않는 가족 구성원으로 둔다(할 일 담당).
- 이미지 대신 단색 블록·SVG 사용.
