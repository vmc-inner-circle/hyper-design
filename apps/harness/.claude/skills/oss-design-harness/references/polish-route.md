# 고치기 루트 — 기존 화면을 시안으로 쓰기

처음부터 루트(`[1]→[6]`)는 그대로 둔다. 이 문서는 **이미 있는 화면을 고칠 때**만 쓴다. 초보 장치(보여 주기, 기본값, 가정 로그, 게이트, Figma 문)는 빼지 않는다. 빠지는 것은 `[1][2][3a][4.5]`의 생성량이다.

청크: `[0' 내 화면 한 장] → [방향 3 중 1] → [내 화면에 입힌 시안] → [이 결로 따라가기] → [4 델타] → [5 표에 남은 화면 Figma] → [6 검증]`

## 초보·기존 UI 검증 (절차·효율)

기준: 한 사이클이 **보이는 결정**으로 끝나야 한다. 초보에게 진단을 시키지 않는다. 한 화면 선택지는 4개를 넘기지 않는다. (Google Design Sprint의 Map → Decide → Prototype을 기존 UI용으로 줄인 것.)

| 단계 | 판정 | 이유 |
|---|---|---|
| 입구 2칸 (처음부터 / 고치기) | 유지 | 새 제품 vs 있는 화면. 세 번째 입구는 인지 비용 |
| 캡처 직후 「왜 어색한지」타이핑 | **폐기** | 초보가 가장 못하는 일. 절차상 산출이 없고 효율 0 |
| 내 화면 한 장 | **맨 앞** | 캡처 + 일 한 줄(추천). 질문 4개를 앞에서 묻지 않음 |
| 방향 3 중 1 (`KIND=reference`) | **고치기 유지** | 창을 눌러 사이트 하나 = 방향 하나. 번호→우리 화면 대응 표는 초보 부하. 하네스가 대응 |
| 내 화면에 입힌 시안 | **추가** | A=지금, B=고른 방향, C=같은 방향 세기만, D=다른 컨셉. 5축 아님 |
| 이 결로 따라가기 | **웹 고치기** | 우리 메뉴 순서를 같은 결로. 새 앱 플로우 아님 |
| 5축·구조 설문 | 고치기에서 제외 유지 | 이미 있는 UI에 신규 앱 인터뷰는 낭비 |
| Figma는 표에 남은 화면 | **웹 고치기** | 고른 결을 메뉴·구성 표의 행에 적용. 창 1장(웰컴)이면 그 창만 |

시간 예산: 설문 ~2분 + 시안 고르기 ~2분 → `[4]`. 그 전에 Figma를 열지 않는다.

이 하네스가 이미 그린 Figma를 고치는 일은 여기가 아니다. 그건 `[6]` 국소 결함 → `STAGE=fix`.

## 시작에서 고치기로 들어오는 조건

입력이 아래 중 하나면 추천은 **있는 화면을 고칠게요**.

| 소스 | 예 | 초보가 가진 것 |
|---|---|---|
| **로컬 화면** | 코드 폴더의 welcome, 데스크톱 창 | 파일 경로, 또는 프로젝트를 연 상태 |
| **라이브 URL** | 운영 중인 웹사이트 | 주소 한 줄. 코드·Figma가 없어도 됨 |
| **캡처** | 스크린샷, 에이전시가 준 시안 JPG | 이미지 파일 |

PRD만 있으면 추천은 **처음부터**. `design/`이 있으면 질문 없이 이어서.

**소스 종류·범위·표면 이동은 사용자에게 고르지 않는다.** 준 것을 보고 하네스가 분류한다. 시작 선택지를 늘리지 않는다.

| 준 것 | 분류 (질문 0) |
|---|---|
| `.html` 폴더, 개발 서버·패키지 없음 | 정적 HTML 한 장. file:// 또는 잠깐 연 뒤 캡처. 실행 앱으로 승격하지 않음. 상대 경로가 깨지면 깨진 그대로 시안 + 가정 로그 |
| 세로로 긴 폰 스크린샷·스토어 캡처·시뮬레이터 창 | 표면 `phone`. 프레임은 이미지/창 픽셀. 스토어 캡처는 크롭일 수 있음 → 가정 로그 |
| URL 하나 | **결을 고를 대표 화면 1장** + 그 페이지에서 보이는 메뉴·같은 호스트 경로를 표로 뽑음. 사이트맵을 묻지 않음. 없는 페이지를 크롤해서 만들지 않음 |
| URL + "앱 만들어줘 / 모바일로 새로" | **처음부터** + 그 사이트는 디자인 요소. 고치기가 아님. 입구에 세 번째 칸을 만들지 않음 |
| 요소(로고·가이드)만 있고 고칠 화면 없음 | "어떤 화면을 고치나요?" 한 줄. 없으면 처음부터 |

고치기를 고른 뒤 **질문 최대 2개** (한 라운드 한 개씩). 둘 다 추천 첫 칸, "모르겠어요" 있음.

1. **무엇을 고치나** — 이미 소스 1개가 보이면 묻지 않고 그걸 쓴다. 여러 개면 `(추천) 지금 연 화면 / 이 주소`.
2. **기존 디자인 요소를 같이 넣나** — `(추천) 이 화면만` / `다른 페이지·브랜드도 넣을게요`. 디자인 시스템 페이지, 브랜드 가이드, 다른 화면 URL, 기존 Figma가 보일 때만 2번을 연다. 없으면 가정: 이 화면만.

**변경 범위(`preserve` / `rebuild`)는 시작 질문이 아니다.** 아래 절.

## [0'] 섭취 — 소스가 달라도 산출은 같다

산출 (brief.md에 적는다):

- 표면: `phone` / `desktop-window` / `popup` / `web`
- 프레임 실제 크기 (예: 880×520, 1440×900, 390×844). **추측으로 390을 씌우지 않는다.**
- 화면 1장의 카피·주요 영역 ≤5개 (번호 라벨 후보). 이 1장이 `[3b]` 시안의 A
- **구성 표:** 헤더 메뉴, 같은 페이지 앵커(`#pricing`), 같은 호스트 경로(`/blog`). 사용자에게 IA를 적게 하지 않음
- 보이는 상태. 안 보이면 빈·로딩·실패는 가정 로그
- 소스 종류와 원본 경로/URL
- (선택) 디자인 요소 묶음: 색·타입·반복 부품. **고칠 화면이 아님** — [4] 델타의 기본값

로그인·권한으로 못 본 페이지는 추측해서 만들지 않는다. "공개된 이 페이지만 봤다"를 가정 로그에 남기고 진행한다.

캡처는 **하네스가 한다.** 초보에게 캡처 도구를 켜 달라고 하는 것은 기본 경로가 아니다. 사용자 개입은 아래 사다리의 실패 칸만.

### 캡처 사다리 (도구)

computer-use(`cu.py`)는 **보이는 데스크톱 창**용이다. 페이지 전용 자동화·임베디드 브라우저는 그 스킬이 제외한다. 공개 URL을 그걸로 열어서 돌아다니지 않는다.

| 무엇이 있나 | 1순위 | 사용자 개입 | 실패 시 |
|---|---|---|---|
| **데스크톱 창** (welcome, 네이티브) | `cu.py --app <앱> --title <제목> shot` → PNG를 `design/references/existing/` | 창이 이미 있으면 0. 꺼져 있으면 실행 1회 | "그 창을 보이게 해주세요" 한 줄 뒤 재촬영. 그래도 안 되면 붙여넣기 |
| **공개 웹 URL** | Figma `generate_figma_design` → 작업 파일에 캡처. **지우지 않는다.** `get_screenshot`으로 허브용 PNG | 주소만 | MCP 실패·봇 차단 → 그 URL이 **이미 열린 브라우저 창**이면 computer-use `shot` (창을 찍는 것. 페이지를 조종하는 것 아님) |
| **localhost** | 위와 같음. 서버가 꺼져 있으면 하네스가 켠다 | 서버 기동은 하네스 | 창이 보이면 computer-use |
| **로그인 벽** | 추측 크롤 금지 | **"로그인한 그 화면을 띄워 주세요"** 한 줄 → 그 창을 computer-use `shot` | 붙여넣기 |
| **디자인 요소 URL** (최대 3) | 고칠 화면과 **같은 사다리**, 허브 탭만 분리 | 주소만 | 동일 |
| **정적 HTML** | 파일을 잠깐 연 창을 computer-use `shot`, 또는 로컬 정적 서버 한 장 후 Figma 캡처 | 폴더만 | 깨진 상대경로 그대로 시안 |

`claude-in-chrome` / `chrome-devtools`는 쓰지 않는다. 그건 하네스가 만든 허브 HTML을 검사하는 용으로 금지된 것이고, 사용자 제품을 가져오는 일도 그 도구로 대체하지 않는다. Playwright MCP가 이 세션에 없으면 새로 달지 않는다 — `generate_figma_design`이 그 자리의 공식 캡처다.

허브 `KIND=existing`에는 항상 PNG가 필요하다. URL 경로면 캡처 노드를 `get_screenshot`한다. 창 경로면 `cu.py shot` PNG를 그대로 쓴다.

### A. 로컬 화면 (코드가 있는 폴더)

1. UI 소스에서 프레임·토큰·카피를 읽는다 (창 크기 상수, CSS 변수, 실제 문구).
2. 캡처 사다리의 **데스크톱 창** 또는 **localhost** 행으로 PNG를 만든다.
3. 코드만으로 [3b]를 시작하지 않는다 — 초보는 코드를 시안으로 못 읽는다.

### B. 라이브 URL (코드 없음, 주소만 아는 초보 포함)

에이전시가 만들어 주고 주소만 아는 경우가 여기다. 사이트맵을 묻지 않는다.

1. 캡처 사다리 **공개 웹 URL** 행. 이 PNG가 `[3b]` 장 A (결을 고르는 대표 화면).
2. 같은 응답에서 **보이는 메뉴·앵커·같은 호스트 링크**만 구성 표로 뽑는다. 링크를 따라 미지의 페이지를 크롤하지 않는다.
3. 일 설문에서 표가 확정된 뒤, 남은 행의 URL·해시만 같은 사다리로 추가 캡처한다 (A 참고용). `[5]`는 고른 결을 그 행들에 적용한다.
4. 고치기에서는 `generate_figma_design` 결과를 기준 레이어로 남긴다. 캡처를 지우고 빈 캔버스에 다시 그리지 않는다 (preserve). D면 새 프레임 + A는 옆에.

### C. 캡처 파일만 있는 경우

받은 이미지를 `design/references/existing/`에 두고 그게 시안이다. 프레임 크기는 이미지 픽셀. 이 경우는 사용자가 이미 개입한 것이므로 사다리를 타지 않는다.

### D. 정적 HTML 파일

서버가 없는 `index.html` 묶음. localhost 앱(A)과 나누어 본다. 패키지 스크립트·창 크기가 있으면 A, 없으면 D. 한 파일을 열어 한 장 찍는다. 링크를 따라 사이트를 재구성하지 않는다.

캡처 실패(404, 주차 도메인, 다운)는 추측 페이지를 만들지 않는다. URL 확인 1회 후 멈춘다. 처음부터로 몰래 바꾸지 않는다.

## 변경 범위 — preserve / rebuild

이전 업데이트의 기본 경로는 **보존(preserve)** 이다. 말하지 않으면 메뉴·위치·흐름을 유지하고 색·간격·카피·위계만 건드린다. **전부 새로(rebuild)** 는 반영되어 있지 않았고, 지금 칸을 연다. 시작 선택지는 늘리지 않는다.

brief.md에 `변경 범위: preserve | rebuild` 를 적는다. 기본값 **preserve** + 가정 로그.

| 사용자가 이미 한 말 | 분류 |
|---|---|
| 색만, 다듬기, 위치는 그대로, 메뉴는 유지, 개선 | preserve |
| 완전히 새로, 구조부터, 메뉴를 갈아, 배치를 바꿔, 흐름을 다시 | rebuild |
| "개선해줘"만 있음 | **preserve** (가정 로그) |

`[3b]` 뒤에만 예외로 한 줄 묻는다. 번호 3개 이상이 내비·메뉴·큰 블록이고 원문이 전체 배치를 가리킬 때:

- (추천) 메뉴·위치는 두고 다듬을게요 → preserve
- 배치부터 다시 그릴게요 → rebuild

추천은 지금까지의 변경 범위. 그 전에는 묻지 않는다.

### preserve

- `[0']→[3b]→[4 델타]→[5]→[6]` 그대로.
- `[5]`는 캡처 레이어를 **고친다.** 메뉴·위치·정보 순서는 `[3b]` 번호가 가리킨 것만 옮긴다. 번호 없는 재배치는 금지.
- 캡처를 지우고 빈 캔버스에 다시 그리지 않는다.

### rebuild

같은 고치기 입구다. 처음부터(`[1]→[6]`)로 갈아타지 않는다. 화면 목적·카피는 유지하고 **뼈대만** 버린다.

- 캡처는 **지금 화면(before, 장 A)** 으로 남긴다. 확정 전에 지우지 않는다.
- 다른 컨셉은 `[3b]`의 **장 D**다. 별도 탭을 만들지 않는다. 같은 카피, 배치만 다름.
- `[4]`는 델타가 아니라 그 화면의 규칙. 출처 `rebuild`.
- `[5]`는 새 프레임을 그린다. A는 옆에 참고로 둔다. 사용자가 새 화면을 본 뒤에만 A를 치운다.

표면을 바꾸는 일(웹 → 모바일 앱)은 rebuild가 아니다. 위의 분류표 "URL + 앱 만들어줘" → 처음부터.

## 기존 디자인 요소 (선택)

고칠 화면과 **섞지 않는다.** 허브에서 고칠 화면 탭과 요소 탭을 나눈다.

넣을 수 있는 것 (최대 3개):

- 다른 페이지 URL (헤더·푸터가 같은지 보는 용)
- 브랜드/가이드 URL 또는 PDF 한 장
- 기존 Figma 라이브러리·파일 링크
- 로컬 토큰 파일 (`:root`, Tailwind theme)

하는 일: 색·타입·반복 부품을 [4] 델타의 **기본값**으로 승격. 사용자가 고치라고 한 화면이 아니면 Figma에 새로 그리지 않는다.

초보가 주소를 더 모르면 `(추천) 이 화면만`으로 닫는다.

## [3a'] 일 설문

`probe-renderer` `KIND=story`. 전문은 `references/story-survey.md`.

웹이면 먼저 **구성 표**(메뉴·페이지에서 뽑음)를 보여주고 추천은 “표 전부에 같은 결”. 창 1장이면 표를 숨긴다. 그다음 **누가 / 일 하나 / 남는 것 / 범위** 질문 4개. 스타일 단어·「왜 나쁜지」·빈 사이트맵 타이핑 금지.

`range=visual`(추천)이면 `[3b]` 추천 리본은 B. `range=job`이면 추천 리본은 D.

## [3a-ref] 레퍼런스 (슬림)

처음부터 3단계의 **레퍼런스 찾기만** 탄다. 5축 취향 시안은 만들지 않는다. 전문 검색·페이지는 `references/reference-sourcing.md` §고치기.

- 스킬이 같은 일(story job)의 사이트·앱 **3개**를 찾는다. 사용자에게 레퍼런스를 달라고 하지 않는다.
- 웹 고치기면 랜딩 페이지 3개(직접 경쟁 2 + 같은 CTA·히어로 문제를 푼 1). 앱·창이면 스토어 캡처 3개.
- 허브 탭 `레퍼런스` (`KIND=reference`). 순서: 이 화면의 일 → **레퍼런스** → 시안.
- 사용자는 번호로 가져올 것 / 싫은 것만 고른다. 앱 전체를 따라 하지 않는다.
- 가져온 번호는 `[3b]`의 C·D에만 넣는다 (배치·위계·CTA). 브랜드 색은 가져오지 않는다. B는 자기 화면 다듬기라 레퍼런스를 섞지 않는다.
- 의견 0건이면 추천 번호 + 가정 로그.

## [3b] 시안 A/B/C/D

`probe-renderer` `KIND=existing`. 같은 카피·같은 일. 프레임은 brief 실측 (`--frame-w` / `--frame-h`). 폰 390을 씌우지 않는다.

| 장 | `data-v` | 무엇을 보여 주나 | 고르면 |
|---|---|---|---|
| **A 지금** | A | `[0']` 캡처 그대로. 대조 | 델타 없음. 기존 화면이 규칙 |
| **B 추천 다듬기** | B | 메뉴·위치 유지. 색·간격·위계만 | preserve + 그 토큰 델타 |
| **C 다른 결** | C | 같은 뼈대, 축 하나만 다름 | preserve + C 토큰 |
| **D 다른 컨셉** | D | 같은 카피·같은 일, **배치만 다른** 한 장 | rebuild. 시작에서 묻지 않던 칸을 눈으로 고름 |

고르는 방법: **창을 누른다.** 추천은 텍스트 한 줄. 「왜」필수 입력 없음. 안 고르고 「다 봤어」면 설문 `range`가 가리키는 추천 장 + 가정 로그.

영역 번호 ①②③ 최대 5, **장마다 같은 자리 같은 번호**. 디자인 요소를 넣었으면 다음 탭. 5축 시안 아님.

사용자가 "다 봤어" → `read_db` `feedback/existing-1` `{best:"A"|"B"|"C"|"D", reaction, text}` → 원문은 brief, 기준은 옆칸.

## [4] 델타

기존 비주얼이 기본값이다. `design-rules.md`를 기본값 표로 복사한 뒤 **[3b]에서 바뀌라고 한 칸만** 덮어쓴다. 나머지 출처는 `기존 화면`. `status: confirmed`는 델타 미리보기(규칙 탭, 바뀐 칸만) 후에 쓴다.

출처 열에 인정되는 값(게이트가 검사): `기존 화면` · `rebuild` · `preserve` · `0'`(섭취) · `3a`/`3b` · `레퍼런스` · `기본값`/`고정`/`자동`.

아이콘 목록은 화면에 보이는 액션만. 없는 화면의 아이콘을 채우지 않는다.

## [5] Figma

`[3b]`에서 고른 결을 `story-map`에 남은 행에 적용한다. 창 1장이고 표가 비었으면 그 창만.

- 시안 A/B/C/D는 **대표 1장**이다. 메뉴마다 A~D를 다시 고르지 않는다.
- 남은 행마다 캡처가 있으면 그걸 기준으로 같은 토큰·위계(B/C) 또는 같은 컨셉(D)을 그린다. 캡처가 아직 없으면 `[0']` 사다리로 그 행만 찍고 진행한다.
- 토큰·라이브러리 신설은 기존 화면에 없을 때뿐.
- URL 캡처가 이미 파일에 있으면 그걸 기준으로 `use_figma`로 고친다. preserve에서 캡처를 지우고 처음부터 다시 그리지 않는다.
- 로컬 코드가 있으면 카피·간격은 코드를 이기고, 픽셀은 캡처를 이긴다. 둘이 어긋나면 brief에 적어 두고 캡처를 시안으로 쓴다.
- 표에 없는 페이지(푸터 약관, 성공 페이지 등)는 그리지 않는다. 가정 로그에 제외를 남긴다.

## [6] 검증

함. `device.frame`은 brief의 실제 크기. 게이트가 390이 아니라고 실패시키면 안 된다.

## 허브 탭 (고치기)

`내 화면` → `방향` → `예상 디자인` → `이 결로 따라가기` → (선택) `디자인 요소` → `규칙 델타`. 5축 취향 탭은 만들지 않는다. 처음부터의 구조 설문은 만들지 않는다.

## 하지 않는 것

- 주소를 받았다고 링크를 따라 미지의 페이지를 크롤하기. 보이는 메뉴·같은 호스트 경로만 표로 뽑는다
- 초보에게 사이트맵·IA·소스 종류·preserve/rebuild를 시작에서 고르게 하기
- 캡처 없이 코드/HTML만 보여주고 취향을 묻기
- 고치기인데 5축 취향 시안(밝기·밀도·형태…)을 새로 그리기. 허용되는 시안은 같은 화면의 A/B/C/D뿐. 경쟁 화면 레퍼런스 3개는 만든다
- 캡처 없이 「왜 어색한지」를 타이핑하게 하기
- preserve인데 캡처를 지우고 빈 캔버스에 다시 그리기
- preserve인데 번호 없는 메뉴·위치를 옮기기. D를 고른 뒤에만 뼈대를 버린다
- 웹→모바일 신규를 고치기 rebuild로 처리하기 (그건 처음부터 + 요소)
- 초보에게 캡처 도구·스크린샷을 기본 경로로 시키기
- computer-use로 웹사이트를 열어 돌아다니기 (그 스킬은 페이지 전용 자동화 제외)
- 404·다운된 주소를 추측해서 페이지를 만들기
