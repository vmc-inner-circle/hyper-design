# 클릭형 로우파이 플로우 — "따라가 보기" 투어

플로우를 다이어그램으로 보여주지 않는다. 그리고 **회색 박스 화면 열몇 장을 한꺼번에 늘어놓지도 않는다.** 디자인 초보 사용자는 그것도 전문 표기법으로 느낀다. 한 번에 화면 하나, 눌러야 할 버튼 하나, 그리고 "누르면 어떻게 되는지"를 이야기처럼 따라가게 한다.

## 시나리오 내러티브 규칙

- 2인칭 현재형. "당신은 앱을 엽니다. 지난번 결과물이 격자로 보입니다."
- 화면 이름(내부 명칭) 대신 **보이는 것**으로 말한다. "홈 화면" 대신 "결과물 격자".
- 한 시나리오는 5~9단계. 그 이상이면 시나리오를 나눈다.
- 시나리오 하나가 1단계에서 정한 핵심 작업 하나에 대응. 최대 3개. 플로우 밖 화면(온보딩·설정 등)은 "부록"으로 붙인다.
- 각 단계 끝에 (①)처럼 화면 번호를 붙인다. 같은 화면이 다른 상태로 다시 나오면 같은 번호를 쓴다.
- 등장 인물·날짜·이름은 brief.md에 한 번 정해두고 모든 시안이 같은 값을 쓴다.

예:
```
시나리오 1 — 지인 등록하고 모임 만들기
1. 앱을 엽니다. 이번 달 달력이 보이고 확정된 모임이 있는 날에 점이 찍혀 있습니다. (①)
2. 하단 탭 "지인풀"을 누릅니다. 사람들이 그룹별로 접혀 있습니다. (⑭)
3. 오른쪽 아래 "+ 지인 추가"를 누릅니다. 이름·연락처 칸과 그룹 칩이 보입니다. (⑮)
…
```

## 투어 페이지 규격 (probe-renderer KIND=flow)

제작·배포는 `probe-renderer`가 한다. 아래는 그 에이전트가 따르는 규격이다.

### 구조
- **한 번에 폰 화면 하나.** 왼쪽 390×844 폰 프레임 1개, 오른쪽 설명 패널. 1280 폭 기준, 좁으면 세로 쌓기.
- 상단: 시나리오 탭(1·2·3·부록)만. **페이지네이션(‹ › · "3 / 8" · 진행 점)과 저장 버튼은 폰 왼쪽 세로 띠(폭 132px, sticky)에** 둔다 — 요소는 가로 배치, 저장 버튼은 띠 폭을 채우는 가로 버튼(높이 40). 키보드 ←→.
- 장면 제목 형식: `장면 3 · 화면 ⑮ 지인 등록`. 화면 번호는 brief §2와 동일한 원문자.
- **눌러야 할 버튼 하나에만** 파란 테두리(펄스) + "여기 클릭 →" 말풍선(폰 프레임 바깥 왼쪽, 버튼 높이에 맞춤 — UI를 가리지 않는다). 누르면 다음 장면. 다른 요소는 눌러도 이동하지 않고 토스트 "이 투어에서는 안 쓰는 버튼이에요".
- **설명용 안내 문구를 넣지 않는다.** "파란 테두리 = 누를 버튼", "①②③ = 화면 구성 번호", "색은 나중에 고릅니다" 같은 범례·주의 문장은 초보자에게 소음이다. 제목 아래 이야기 한 줄만 둔다. 페이지가 스스로 설명되어야 한다.

### 오른쪽 패널 — 항상 같은 5칸, 같은 순서
1. **지금 상황** — 시나리오 문장 그대로.
2. **화면 구성** — 영역 3~5개만 번호로 (① 제목줄 ② 본문 ③ 하단 버튼 ④ 탭바). 폰에도 같은 번호를 작은 반투명 배지로. **버튼마다 번호를 붙이지 않는다. 화면당 라벨 최대 5개.**
3. **누르면 이렇게 돼요** — 칩 3~4개: `누름 → 잠깐 로딩 → 성공: …` / `실패하면: …`. 그 아래 **"이 화면의 다른 모습" 세그먼트**: 기본 · 눌렀을 때 · 로딩 중 · 성공 · 실패 · 비어있음 · 비활성. 고르면 폰 내용이 그 상태로 바뀐다. 해당 없는 상태는 흐리게 + "없어요".
4. **시선 흐름** — "위→아래: ① 제목에서 읽고 → ② 본문에서 고르고 → ③ 하단 버튼으로 끝냅니다" + "흐름 화살표 보기" 토글(폰 위에 점선 ①→②→③).
5. **이 장면, 어때요?** — 의견 패널. 아래 "의견 수집" 참고.

### 배치 일관성 (모든 화면 공통 템플릿, 예외 없음)
- 상태바 44 / 상단 바 56(왼쪽 뒤로‹ 또는 닫기×, 가운데 제목, 오른쪽 액션 최대 1개) / 본문 / 하단 고정 CTA 바(버튼 52, 좌우 20) / 홈 인디케이터 34.
- 루트 화면만 탭바. 바텀시트는 부모 화면 위에 딤 + 시트. 링크로 여는 게스트 화면은 상태바 아래 회색 "주소창" 띠.
- 리스트 행 56, 카드 패딩 16, 라운드 12, 칩 28. 화면당 primary 버튼 1개, 위치는 항상 하단 고정.

### 시각 스타일
- 취향 시안이 아니므로 중립. 그러나 **회색 박스 와이어프레임은 금지** — 초보자에게는 그것이 더 어렵다.
- 배경 #F7F8FA, 카드 흰색 + 1px #E5E7EB, 본문 #1F2937, 보조 #6B7280. 강조색 딱 하나 #2F6BFF(primary 버튼·누르세요 테두리·활성 탭). 실패만 #DC2626.
- 시스템 폰트 스택. 아이콘 없음(‹ × + ✓ 문자만). 이미지 없음. 더미 텍스트는 brief의 도메인 언어.

### 상태 변형 최소 요구
- 폼 화면: 기본 / 눌렀을 때 / 로딩 / 성공 / 실패 / 비어있음(필수값 없음 → 버튼 흐림)
- 목록·상세 화면: 기본 / 로딩 / 비어있음
- 선택 화면: 기본 / 비어있음 / 비활성(0개 선택)
- 나머지: 기본 + 로딩

## 의견 수집 — 페이지 안에서 고르고 적는다

사용자에게 "번호를 말해달라"고 하지 않는다. 각 장면 패널 5번 칸에서 바로 고르고 저장한다.

- 기본은 버튼 두 개: **"괜찮아요 👍"**(즉시 저장 reaction:"good") / **"어색해요 🤔"**. 👎는 없다.
- 🤔를 눌렀을 때만 영역 번호 칩(①②③④…) 토글 + 자유 입력이 펼쳐지고 왼쪽 띠의 가로 저장 버튼이 활성화된다 → "저장됨 ✓". 의견 있는 장면은 진행 점에 표시.
- 페이지 맨 아래 "전체 의견" 1개.

저장은 Artifact `db` capability (`capabilities: {db: {}}`). 문서 경로 `feedback/scene-<장면번호>`, 전체는 `feedback/overall`. 본문 `{scene, screen, reaction: "good"|"confusing"|"bad"|null, marks: ["③"], markNames: ["하단 버튼"], text, updatedAt}`. `set()`으로 통째 저장. 열 때 `db.collection("feedback").get()` 1회로 복원. `claude.use("db")`가 null이면 localStorage 폴백 + "이 환경에서는 브라우저에만 저장돼요" 안내.

## 메인 대화가 하는 일

1. probe-renderer가 돌려준 **장면 ↔ 화면 ↔ 영역 번호·이름 대응표**를 보관한다.
2. 사용자에게 링크를 주고 "다 보시면 말씀해 주세요"만 말한다. 터미널 질문은 하지 않는다.
3. 사용자가 "다 봤어"라고 하면 `Artifact(action: "read_db", db_op: "list", collection: "feedback")`로 읽는다. 대응표로 `marks`를 영역 이름으로 풀어 brief.md §2에 원문(text) + 해석을 남긴다.
4. 의견이 0건이면 그때만 터미널로 묻는다: "막힌 장면이 있었나요? (없음 / 장면 번호)", "순서가 이상한 곳이 있나요?" 두 개.
5. 🤔가 붙은 장면만 골라 수정 시나리오를 만들고, 그 장면만 다시 보여준다. 로우파이 전체를 다시 만들지 않는다 (화면 추가·삭제 수준일 때만).
6. 반응이 없거나 전부 👍인 장면의 primary CTA는 파란 버튼 그대로 확정하고 brief §2 "화면별 primary CTA" 줄을 채운다.
