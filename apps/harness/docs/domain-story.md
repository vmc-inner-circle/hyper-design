# 도메인 스토리 — 사용자와 하네스의 목적 겹치기

도메인 스토리텔링(Hofer & Schwentner)으로 **누가 / 무엇을 / 어떤 순서로** 다루는지 맞춰 간다.
이 파일이 공통 언어의 첫 자산이다. 합의된 문장만 남기고, 어긋난 문장은 고친다.

표기: `배우` 는 **작업물** 을 *활동* 한다. 번호는 시간 순서.

---

## 1. 배우 (Actors)

| 배우 | 이 도메인에서 하는 일 |
|---|---|
| **사용자** | 제품 화면을 고치고, Figma에서 결과를 보고, “이 정도면 됐다”를 내린다 |
| **하네스** (스킬+에이전트) | 판단 기준을 뽑고, 시안을 보여 주고, 규칙으로 고정한 뒤 Figma에 그린다 |
| **Figma** | 산출물이 사는 곳. Dev Mode에서 사용자가 직접 연다 |
| **게이트** (`check_phase` / `figma_audit`) | “끝났다”를 하네스가 말하지 못하게 막는다 |

---

## 2. 사용자 스토리 (하려는 목적)

1. 사용자 는 **이미 있는 화면**(예: dictionary welcome 880×520) 또는 **새 PRD** 를 가져온다
2. 사용자 는 하네스 에게 *가벼운 개선* 또는 *제품 단위 디자인* 을 맡긴다
3. 사용자 는 **시안** 을 보고 *좋다/싫다 + 왜* 를 남긴다 (말로 스타일을 설명하지 않는다)
4. 사용자 는 **Figma 파일** 을 받는다 — 산출물의 집은 코드가 아니라 Figma다
5. 사용자 는 **Figma Dev** 에서 그 파일을 *열어 확인* 한다
6. 사용자 는 통과하면 *이 정도면 됐다* 를 내린다. 아니면 고칠 자리만 가리킨다

핵심 문장: **규모가 다른 두 일(가벼운 창 다듬기 / 모바일 그린필드)을 한 하네스가 다루되, 나가는 문은 항상 Figma다.**

---

## 3. 하네스 스토리 (원래 목적)

1. 하네스 는 **PRD** 를 읽는다
2. 하네스 는 사용자 와 **구조 → 플로우 → 레퍼런스·취향 → 규칙** 을 *인터뷰* 한다
3. 하네스 는 **허브 HTML** 에 시안을 쌓고 사용자 가 *페이지 안에서 고르게* 한다
4. 하네스 는 **design-rules.md** 에 `status: confirmed` 를 쓴다
5. 하네스 는 **Figma** 에 토큰 → 컴포넌트 → 화면 을 *STAGE 단위로* 그린다
6. 게이트 는 **스냅샷** 을 *수치 검사* 하고, 하네스 는 스크린샷을 *눈으로* 본다
7. 실패하면 하네스 는 **국소 결함 / 방향 오류 / 반복 실패** 로 *라우팅* 한다

핵심 문장: **디자이너 순서를 흉내 내지 않고, 판단 기준만 뽑아 Figma에 심는다.**

---

## 4. 겹침과 어긋남

```
사용자 1──가져온다──▶ [화면 또는 PRD]
하네스 1──읽는다──▶ [PRD 또는 기존 화면]  ← 겹침 (두 입구)

사용자 2──맡긴다──▶ [가벼운 일 | 큰 일]
하네스 2──인터뷰한다──▶ [루트별 단계]     ← 겹침 (고치기는 일 설문→시안 A/B/C/D)

사용자 3──고른다──▶ [시안]
하네스 3──보여준다──▶ [시안]          ← 겹침

사용자 4──받는다──▶ [Figma 파일]
하네스 5──그린다──▶ [Figma 파일]      ← 겹침 (합의: 산출물은 Figma)

사용자 5──확인한다──▶ [Figma Dev]
하네스 ──연결됨──▶ [Figma Dev]        ← 겹침 (원격 MCP)

사용자 6──판정한다──▶ [이 정도면 됐다]
하네스 6──검사한다──▶ [게이트]        ← 겹침 (최종은 사람)
```

| 작업물 | 겹침 | 할 일 |
|---|---|---|
| **Figma 파일** | 둘 다 나가는 문 | 유지. 코드 반영은 Figma 다음 단계이지 대체물이 아님 |
| **시안** | 둘 다 “보여 주고 고른다” | 유지. 프레임 크기만 표면 프로필로 바꾼다 |
| **규칙 문서** | 하네스만 명시, 사용자는 “정해진 스타일” | 공통 자산으로 승격. 가벼운 일은 델타만 |
| **PRD** | 하네스는 필수, 사용자는 선택 | 입력을 `PRD \| 기존 화면+제약` 으로 연다 |
| **허브 HTML** | 하네스의 고르는 장 | 유지하되, 사용자가 보는 최종은 Figma Dev |
| **390×844** | 하네스만 고정 | 표면 프로필로 분리 (phone / desktop-window / popup) |

---

## 5. 공통 스토리 (합의본, 이 세션)

1. 사용자 는 **작업 종류**(polish / greenfield) 와 **표면**(phone / desktop-window / popup / web) 을 하네스 에게 넘긴다. feature는 polish로 취급한다.
2. 하네스 는 그에 맞는 단계만 돌리고, 건너뛴 단계는 가정 로그에 남긴다
3. 사용자 는 **시안** 을 보고 고른다
4. 하네스 는 **규칙**(전체 또는 델타) 을 확정한다
5. 하네스 는 **Figma 파일** 을 그린다 (토큰 → 부품 → 화면, 가벼운 일은 해당 화면만)
6. 사용자 는 **Figma Dev** 에서 연다
7. 게이트 가 수치를 통과시키고, 사용자 가 *이 정도면 됐다* 를 내린다

이 스토리에서 빼지 않는 것: 보여 주기, 기본값, 가정 로그, 스크립트 게이트, Figma가 산출물.

---

## 6. 쌓을 공통 자산

| 자산 | 역할 | 상태 |
|---|---|---|
| 이 문서 | 배우·작업물·순서의 공통 언어 | 초안 |
| 표면 프로필 + 작업 트랙 | 1번 활동의 입력 | 두 입구. 소스 분류는 하네스. 고치기 기본은 preserve. rebuild는 시안 D를 고르는 것 |
| `.mcp.json` / `.grok/config.toml` | 하네스 ↔ Figma 연결 | 원격 `figma` 인증됨 (37 tools). 로컬 3845는 쓰지 않음 |
| `design-rules.md` (또는 델타) | 시안과 Figma 사이의 계약 | 템플릿만 있음 |
| Figma 파일 | 사용자가 Dev에서 보는 산출물 | 연결 후 생성 |

---

## 7. 환경 메모 (연결)

- 원격 MCP: `https://mcp.figma.com/mcp` — 세션에 `figma` 37 tools. OAuth는 이름마다 한 번.
- 데스크톱 MCP `127.0.0.1:3845`는 쓰지 않는다. 원격과 같이 두면 `use_figma`가 안 붙는다.
- 고치기 URL 섭취는 `generate_figma_design` 캡처를 기준 레이어로 남긴다. 지우지 않는다.
