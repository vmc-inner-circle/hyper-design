# 보이스톤 프리셋 — 합격 기준과 자동 개선 루프 (초안)

1차 실험(`docs/voice-experiment.md`)에서 배운 것: 판정이 내용 단서로 맞히고, 상황 설명이 느슨하면 잡음이 크다. 기준은 **측정이 믿을 만할 때만** 의미가 있으므로, 측정 조건(0절)을 먼저 고정한다.

## 0. 측정 조건 — 이게 깨지면 아래 숫자는 무의미하다

| 조건 | 내용 |
|---|---|
| 정답지 분리 | 회사마다 실제 본앱 문장(OCR 검증된 것)을 **dev 60% / test 40%**로 고정 분할(시드 고정). 루프는 dev만 본다. test는 사람이 정한 시점에만 연다. |
| 최소 표본 | test 문장 **회사당 30개 이상**. 지금 리디는 본앱 14개라 미달 — 리디는 추가 수집 전까지 '잠정'. |
| 내용 통제 | 실제 문구 → **영어로 뜻만 옮긴 메모**(별도 모델, 고정) → 프리셋이 한국어로 다시 쓴다 → 원문과 비교. 후보끼리 내용이 같고 말투만 다르게 만든다. 영어를 거치므로 직역투 저항도 함께 잰다. |
| 판정 고정 | 판정 모델·프롬프트·온도 고정. 같은 판정을 2회 돌려 일치율(κ) 0.6 이상이어야 그 회차를 믿는다. |
| 잡음 바닥 | 같은 프리셋으로 평가를 3회 반복해 점수의 표준편차(σ)를 잰다. **개선은 2σ를 넘을 때만 개선**으로 인정. |
| 누출 차단 | 프리셋 파일과 정답지(dev·test)의 6글자 이상 겹침 0. 프리셋 크기 상한(예: 8KB) — 정답을 외워 넣는 과적합 방지. |

## 1. 유효하다 — 그 회사답다

| 지표 | 합격선 | 왜 이 선인가 |
|---|---|---|
| V1 같은 상황 비교: 실제 원문과 말투가 가장 닮은 후보로 **자기 프리셋**이 뽑힌 비율 | **≥ 60%** (우연 33%) | 1차 리디 71%, 토스·당근 50% — 리디 수준을 해요체 둘에도 요구 |
| V2 말투 지문: 프리셋 결과의 지문이 세 회사 실제 지문 중 자기 회사에 가장 가깝고, 그 거리가 **회사 사이 실제 거리의 절반 이하** | 3/3 회사 | 가깝기만 하고 여전히 멀면 '덜 다른 것'일 뿐 |
| V3 사람 진짜 찾기: 그 앱을 평소 쓰는 사람이 실제 vs 프리셋 결과 쌍에서 진짜를 맞힌 비율 | **≤ 65%** | 50%면 완전 구별 불가 — 65%는 '대체로 헷갈림' |

## 2. 쓸만하다 — 하네스 결과물이 나아진다

| 지표 | 합격선 |
|---|---|
| U1 규칙 준수(문체·경어·버튼 짝·공통 문법) | ≥ 98% |
| U2 데이터 보존(숫자 값을 바꾸지 않음 — 1천=1,000 같은 표기 차이는 같게) | ≥ 95% |
| U3 v18 원본 대비 더 자연스럽다(사람 쌍 비교) | ≥ 80% |
| U4 '공통 문법만' 대비 나쁘지 않다(사람 쌍 비교) | ≥ 50% — 프리셋이 문법 위에 얹는 값이 있어야 한다 |
| U5 서로 구별된다(이름·한 줄 설명만 보고 맞히기) | ≥ 80%, 어느 두 프리셋 사이 혼동도 20% 미만 |

U5를 못 넘는 두 프리셋은 합친다(사용자에게 차이 없는 선택지를 주지 않는다).

## 3. 재현된다 — 언제든, 어디서든

| 지표 | 합격선 |
|---|---|
| R1 반복 안정성: 같은 프리셋 3회 평가의 V1 표준편차 | ≤ 5%p |
| R2 생성 모델 교체(sonnet → haiku, 하네스가 실제로 쓸 수 있는 가장 싼 모델) | V1 하락 ≤ 10%p |
| R3 새 도메인: v18에 없던 PRD 2개(예: 병원 예약, 중고 거래)로 U1·U5 다시 | 합격선 유지 |
| R4 판정 교체(opus → sonnet 판정)와의 일치율 | κ ≥ 0.6 |
| R5 동결: 합격한 프리셋에 `version`·`verified`(날짜·지표값·평가 커밋) 기록, 평가 스크립트 한 줄로 재실행 | 기록 있음 |

**합격 = 0절 조건 충족 + 1·2·3절 모두 통과 (test 셋 기준).** 사람 지표(V3·U3·U4)는 루프 밖, 마지막에 한 번.

## 4. 자동 개선 루프 — Karpathy autoresearch 방식

autoresearch의 핵심만 옮긴다: **고칠 수 있는 파일은 하나, 평가는 고정, 시간 예산 고정, 점수 하나, 좋아지면 커밋·아니면 되돌림, 모든 시도를 기록.** 사람은 평가가 아니라 연구 지침(`program.md`)을 고친다.

| autoresearch | 여기 |
|---|---|
| `train.py`(에이전트가 고치는 유일한 파일) | `foundation/voices/<slug>.json` — 한 번에 프리셋 하나 |
| `prepare.py`(고정 평가·데이터) | `loop/voice_exp.py eval --split dev`, 정답지, 판정 프롬프트 — 수정 금지 |
| 5분 학습 예산 | 1회 평가 약 3분(생성 9회 + 판정 ~10회) |
| `val_bpb` | **dev 점수 = V1 평균 − 미달 패널티**(U1 98% 미만, U2 100% 미만, U5 혼동 20% 이상이면 큰 감점) |
| `results.tsv` | `loop/voicetone_runs.tsv` — 시도, 가설, 바꾼 곳, 점수, σ, 유지/폐기 |
| `program.md` | `loop/voicetone_program.md` — 연구 지침(아래) |

**한 회차(서브에이전트 1개)**
1. 지침·최근 기록·현재 최고 프리셋·**dev에서 틀린 사례**(실제 원문 vs 자기 프리셋 결과)를 읽는다.
2. 가설 하나를 세운다(예: "당근은 묻는 자리에서 '-시-'를 쓴다 — 존칭 최소화가 과했다").
3. 프리셋 파일 하나만 고친다. 정답지 문구를 옮겨 적지 않는다(누출 검사가 막는다).
4. 평가를 돌린다. 2σ 넘게 좋아지면 커밋, 아니면 되돌린다. 기록에 한 줄.

**오케스트레이터**(`loop/voicetone_auto.py`, 백그라운드 작업으로 실행): 회차를 N번(예: 프리셋당 10회, 총 30회 ≈ 2시간) 순서대로 돌리고, 5회마다 잡음 바닥(σ)을 다시 잰다. 끝나면 test 셋으로 한 번 평가하고 요약을 남긴다. test를 루프 안에서 보지 않는 것이 과적합 방지의 핵심.

**루프가 하지 않는 것**: 평가 스크립트·정답지·판정 프롬프트 수정, 공통 문법 수정, 프리셋 추가·삭제(합치기는 사람이 U5를 보고 결정).

## 5. 루프 전에 할 일

1. 리디 본앱 문장 추가 수집(30개 이상, OCR 검증) — 안 되면 리디는 '잠정'으로 루프 제외
2. `voice_exp.py`에 `eval --split dev|test`, 영어 뜻 메모 단계, 판정 2회 일치율, 반복 σ, 누출 검사 추가
3. 기준선 측정: 현재 프리셋으로 dev 3회 → σ와 출발 점수

## 6. 합격선 정하는 법과 바꾸는 규칙

**숫자를 감으로 정하지 않는다 — 측정 도구의 바닥과 천장을 실측해 그 사이에 둔다** (`loop/voicetone_auto.py thresholds()`).

- 바닥 = 자기 프리셋 자리에 '공통 문법만'(보이스톤 없음) 결과를 넣었을 때 V1. 천장 = 실제 원문을 **말투는 그대로** 표현만 바꿔 쓴 것을 넣었을 때 V1(이 측정으로 얻을 수 있는 최대).
- **합격 = 바닥 + (천장 − 바닥) × 0.5**, 목표(stretch) = × 0.75. 천장 − 바닥 < 0.15면 측정이 변별하지 못한다 — 루프를 멈추고 평가부터 다시 설계.
- 개선 인정 = 같은 프리셋 3회 평가의 표준편차 σ(최소 0.02) 기준 — 1회 평가가 +σ 넘으면 확인 평가 1회, 두 번 평균이 +1.5σ 넘을 때만 유지. σ > 0.05면 측정이 너무 흔들린다는 뜻 — 판정 반복 수를 늘린다.
- U1 98%·U5 80%는 사용자 안전·선택지 의미에 관한 원칙이라 실측과 무관하게 고정.

**기준을 바꿔도 되는 경우** (바꿀 때마다 아래 이력에 이유와 함께):
1. 측정 도구가 바뀜(정답지 추가, 판정 모델·프롬프트, 뜻 메모 방식) → 바닥·천장·σ 재측정 후 공식으로 다시 계산.
2. 지표가 엉뚱한 것을 잰다는 증거(예: 1차의 '회사 맞히기'가 내용으로 맞힘) → 지표 폐기·교체.
3. 사용자 가치에 대한 새 이해(예: 사람 평가에서 V1이 높아도 어색하다는 결과).

**바꾸면 안 되는 경우**: 프리셋이 합격선을 못 넘어서 낮추는 것. 루프가 본 dev 결과로 test 합격선을 고치는 것.

### 기준 변경 이력
- 2026-10-12: U2 100% → ≥95%, 숫자 표기 정규화. 이유: 스모크 평가에서 '1천P'→'1,000P' 같은 표기 차이를 손실로 셌다(지표 오류). 시각 체계 변경(11시→23:59)은 계속 손실로 잡는다.
- 2026-10-12 (루프 8회차에서 중단·수정): 점수에서 U1·U2 감점 제거 → **점수 = V1(회사다움)만**, U1 ≥ 98%·U2 ≥ 95%는 회차 거절 관문. 이유: 기준선 U2가 0.89~0.95를 오르내려 0.2 감점이 켜졌다 꺼지며 점수를 흔들었다(8회차 0.537은 감점이 꺼진 것). U2 정규화 보강 — 앞자리 0 무시(04=4), 가림 표시가 있는 원문 제외. 생성 묶음 실패 시 재시도(토스 문항이 58→38로 줄던 문제). 1~8회차 tsv의 score 열은 옛 계산(감점 포함)이다.
