# 성공 기준 — 결과물 정량 게이트

하네스 결과물(HTML)이 통과해야 할 기준. 근거는 [design-criteria.md](./design-criteria.md).
측정은 브라우저에서 렌더링된 결과(computed style)를 Playwright로 읽는다 — 코드를 어떻게 짰든 같은 잣대로 잰다.

## 0. 프로세스

- 수행 시간 **< 15분** (PRD 입력 → 최종 HTML)
- 사용자 개입 **≤ 4회** (PRD 입력 포함)
- 질문 속 전문 용어 **0개** (금칙어 사전)
- 사용자 답이 선택형인 비율 **100%** (`B`, `1A 2B`처럼 10자 이내)

## 1. 완결성

- 화면 수 **≥ 12**
- PRD 커버리지 **100%** — 기능 요구사항·유저스토리가 각각 1개 이상의 화면에 매핑
- 도달 불가 화면 **0**, 데드링크 **0** (`index.html`에서 클릭으로 모두 도달)
- 플레이스홀더 **0** (lorem, TODO, "텍스트", "여행 1", 깨진 이미지, 콘솔 에러)

## 2. 상태 — 빠짐도 넘침도 실패

상태는 화면 속성에서만 파생한다.

- `empty` ← 목록 화면 + 첫 사용 진입 경로가 있음
- `error` ← 폼 화면
- `disabled` ← 읽기 전용 역할이 존재
- `loading`·`success`는 상태로 만들지 않는다. 짧은 대기는 스켈레톤, 긴 작업(외부 의존·취소 불가)은 별도 화면.
- 경계값(긴 제목, 항목 0/많음)은 상태가 아니다. default 화면의 더미 데이터로 확인한다.

게이트: 파생된 상태 누락 **0** · 규칙에 없는 상태 **0** · 화면당 default 포함 **≤ 3**

## 3. 일관성

- 무채색 외 색상 **≤ 2** (포인트 컬러), 회색 단계 **≤ 6**
- 폰트 크기 **≤ 7**종, 굵기 **≤ 3**종, 패밀리 **≤ 2**종
- 여백·크기 값이 4의 배수인 비율 **≥ 95%**
- border-radius **≤ 4**종, 그림자 **≤ 3**종

## 4. 가독성·접근성

- 명도 대비 WCAG AA 위반 **0** (axe-core)
- 최소 글자 크기: 전체 **≥ 12px**, 읽기 전용 역할(부모) 화면 본문 **≥ 16px**
- 터치 영역 **≥ 44×44px** 비율 100%
- 375px 폭에서 가로 넘침 **0**, 요소 겹침·텍스트 잘림 **0**

## 5. 위계·덜어내기

- 화면당 주요 버튼(채워진 강조색) **≤ 1**, 제목(h1) **= 1**
- 같은 목적 CTA 중복 **0**
- 섹션별 {대상, 시점} 명시율 **100%** (하네스 산출 문서 기준)
- 도움말/툴팁/물음표 아이콘 **0**

## 6. AI 슬롭

- 이모지 아이콘, 보라·파랑 그라데이션, 텍스트 그라데이션 **0**
- 카드 3단 이상 중첩 **0**, radius 적용 컨테이너 비율 상한(값은 첫 구동 후 캘리브레이션)

## 7. 종합 품질 (평가 에이전트)

- C단계 비평 **P0·P1 = 0건**
- 루브릭(위계·이해 가능성 / 덜어내기 / 일관성 / PRD 갈등 해결 / 역할별 차이) 평균 **≥ 4.0/5**, 최저 **≥ 3**
- 바닐라(하네스 없는 Claude Code, 같은 PRD) 대비 블라인드 비교 승률 **≥ 80%** (5회 판정)

## 8. 미적 파운데이션 (컬러·타이포·스페이싱)

9/30 싱크 결론: 디자이너 결과물이 예쁜 근거는 컬러 시스템·타이포그래피·스페이싱 세 가지로 귀결된다. 1~6이 "나쁜 것을 막는" 기준이라면 이 절은 "예쁘게 만드는" 기준이다.

- 순검정(`#000`)·순흰 글자 외 하드코딩 **0**, 본문 글자색은 `#000`이 아닌 토큰(예: `#191F28`)
- 타이포 대비: 화면 첫 제목 ÷ 본문 크기 **≥ 1.5**, 제목 굵기 − 본문 굵기 **≥ 200**, 보조 글자는 본문보다 **작거나 옅게**(둘 중 하나 이상)
- 여백: 텍스트 블록 사이 최소 간격 **≥ 8px**, 섹션 사이 **≥ 24px**, 화면 좌우 여백 **≥ 20px** — "다닥다닥 붙은" 화면 방지
- 모든 색·크기·간격은 파운데이션 패키지에서 온다(파운데이션 밖 값 **0**)

## 9. 화이트보드 단순성

처음 보는 사람이 설명 없이 읽을 수 있어야 한다. 근거: 성렬님 보드(조작 요소 과다·1280 화면 0.6배 축소로 글자 7~9px), 여진님 보드(Excalidraw 로딩 15초·10% 줌·편집 툴바 노출), "피그마는 기능이 숨겨져 있어 움직이기만 해도 브라우징된다".

- 첫 화면(1440×900)에 보이는 버튼·토글 **≤ 3개**, 조작 모드(편집·선택·범위) **0개**
- 외부 라이브러리·설치 **0개**, 캔버스 로딩 **< 1초**
- 화면 축소 배율 **≥ 0.7**(본문 16px → 11px 이상으로 읽힘)
- 화살표는 분기에만: 화살표 수 **≤ 그룹 수 + 분기 수**, 교차 **0**. 순서는 배치(왼→오)로 보여준다
- 흐름은 큰 단위(온보딩·홈·주요 기능)로 그룹핑, 한 줄 = 한 흐름
- 사용자가 밟는 오류·성공 상태는 해당 흐름 줄 안에 배치
- 화면 아래 설명·정책 **≤ 3줄**(나머지는 접기)
- **처음 보는 사람 테스트**: 비개발자 가상 사용자에게 캔버스만 보여주고 "이 앱 흐름 설명", "X를 하려면 어느 화면?" 과제 성공률 **≥ 90%**, 조작법 질문 **0건**

## 10. 레퍼런스 대비 품질

루브릭(Claude의 취향)만으로 최적화하면 Claude 기본값으로 수렴한다. 실제 앱을 기준점으로 쓴다.

- 같은 도메인 한국 앱 실제 화면(uibowl) 옆에 나란히 놓고 "실제 출시된 앱처럼 보이는가" 블라인드 판정 — 레퍼런스와 구분 불가 또는 근접 **≥ 50%**
- 사람 만족도(1~5) 매 반복 기록, 평가 에이전트 점수와 어긋나면 에이전트 루브릭을 보정
