## 1. 핵심 결론 (요약)

1. **앱바, 섹션 제목, 버튼, 배지, 토글 라벨은 거의 모두 명사구다.** 국내 앱 스크린샷에서 옮긴 섹션 제목 약 35개 가운데 문장형은 2개뿐이다(TS "추천 상품으로 시작해요", DG "이웃들이 찾는 가게는?"). **조건절("~하면", "~나면")로 끝나는 섹션 제목은 하나도 없었다.** 번역 앱 8종을 key 이름으로 분류해 봐도 title과 button은 레지스터와 관계없이 명사, 라벨형, `~기`형이 55~90%다.
2. **큰 숫자는 "라벨(명사) + 숫자·단위" 두 줄 구조다.** CT「나의 순서 / **3**번째 / 웨이팅 번호 25번」, TB「현재 내 순서 : 5번째」, BC「1명 남음 | 정원 4명」. "내 순번은 5번"처럼 주제 조사 '은'으로 문장을 시작한 사례는 없다.
3. **완료는 "명사형 제목(완료·성공) + 다음 일을 알리는 문장 1개", 이렇게 두 층으로 나눈다.** KM「알림 신청 완료」+「모임이 시작되면 알림으로 바로 알려드릴게요.」, BC 푸시「그룹수업 예약 성공!」. 두 문장을 줄표로 이은 실제 예는 국내 화면과 코드 어디에도 없었다. 번역 파일 1.6만여 개 문자열 중에서도 MM 14건, MST 1건뿐이다.
4. **사실 여러 개는 문장이 아니라 "·"나 "|"로 이은 명사 메타 줄, 또는 라벨|값 행으로 쓴다.** CT「영업중 · 07:00-21:30」, BC「예약마감 | 정원 4명」, SM「취소 / 수업 시작 2일 5시간 30분 전까지」, BM「분식 3,000원 이상 픽업 주문 시」.
5. **"~할 수 있어요"는 화면 안보다 App Store 설명문에 몰려 있다.** 설명문: 당근 13회, 토스 12회, 테이블링 11회. 화면 안에서는 가치를 제안하는 제목(TS「1분 만에 대출 금리·한도 확인할 수 있어요」)이나 기회 알림(BC 푸시「…수업을 예약할 수 있어요~」)에만 드물게 쓴다. 다만 토스는 에러 메시지에서 "~해야 해요" 대신 "~할 수 있어요"를 **권장**한다(TE). 그러니 규칙은 '금지'가 아니라 **"자리를 가려 쓴다"**여야 한다.
6. **해요체 대 합니다체는 앱마다 다르고, 한 화면 안에서 섞이기도 한다.** CT는 경고 박스 제목을 해요체로 쓰고(「잠깐, 노쇼는 안돼요」) 본문 불릿은 합니다체로 쓴다(「노쇼 시 캐치테이블 앱 이용이 제한될 수 있습니다.」). 규칙 대상은 레지스터 통일보다 **자리별 형태(명사냐 문장이냐)와 문장 수**가 맞다.
7. **번역 앱(합니다체 위주)은 버튼과 제목 형태를 참고할 좋은 예이지만, 문장은 직역투 반례로도 쓸 수 있다.** "당신"이 WP 48, MM 25, BW 18, MST 15회 나오는데 국내 코드 SNUTT와 KM에서는 0회다. 「당신의 홈 타임라인은 비어있습니다! 더 많은 사람을 팔로우하여 채워보세요.」(MST) 같은 문장이 그 예다.

## 2. 자리별 실제 문구

### 2.1 앱바 제목: 전부 명사구(동작 명사 포함), 문장은 0
- 방문예정 (CT), 내 주변 찾기, 전국 Top 100 (TB), 예약내역, 역선택, 좌석선택 (SRT)
- 모바일 회원증, 마이핏, 커뮤니티 (BC), 당근알바, 당근부동산, 당근중고차 (DG), 내 클래스 (C101)
- 수업 예약, 알림 (SM), 빈자리 알림 (SNUTT `vacancy_app_bar_title`), 모임 만들기, 마이페이지, 모임 의견내기 (KM)
- 번역 앱도 같다: 새 게시물, 프로필 편집, 팔로우 요청 (MST)

**경향**: 화면이 무엇인지 알리는 명사(방문예정, 예약내역) 또는 '명사+동사 명사형'(역선택, 모임 만들기)으로 쓴다.
**[추론]** 앱바는 화면을 오가는 내비게이션 라벨이라 탭 이름이나 바로 전 버튼 라벨과 짝을 이룬다(버튼「모임 만들기」에서 앱바「모임 만들기」로, KM). 그래서 문장일 이유가 없다.

### 2.2 섹션 제목: 명사구가 압도적, 조건절은 0
실제 예 (국내 화면):
- 나의 순서, 등록 정보, 레스토랑 공지, 인원, 시간, 가격대별 BEST (CT)
- 요일별 대기시간 통계, 영업정보, 이용 정보 (TB)
- 최근 쓴 계좌, 내 계좌, 내 투자, 해외주식, 혜택 (TS)
- 서초동 이웃들이 많이 찾는 알바, 지금 인기있는 차, 강남구 추천 매물, 진행중인 거래, 최근이용내역 (DG)
- 최근 입장내역, 운동 목표, 내 신체기록 (BC), 결제 수단 선택 (SRT)
- 전국 많이 찾는 장소, 그리니님을 위한 AI 추천 장소, 오늘 방문 가능한 음식점, 서초구 반포동 주변 예약 (NM)
- 이용·예약 서비스 (KT), 배민클럽 전용 쿠폰팩 (BM), 지금 바로 받을 수 있는 차 23대 (SC)
- Classmate 님을 위한 추천 클래스 (C101), 예약 및 취소 가능 시간, 사용 수강권 (SM, 저해상 판독)
- 오늘 참여할 수 있는 모임, 미리 보는 내일 모임 (KM)

문장형 예외(2/35): 「추천 상품으로 시작해요」(TS), 「이웃들이 찾는 가게는?」(DG, 질문형)

**경향**
- 수식어는 앞에, 명사는 끝에 둔다: "[누가/언제] + [무엇]" (서초동 이웃들이 많이 찾는 **알바**, 오늘 방문 가능한 **음식점**). 관형절이 길어도 마지막은 명사다.
- "내 / 나의 / 최근 / 지금 / 오늘"을 앞에 붙여 범위를 정한다.
- **"~하면 / ~나면 / ~할 때"로 끝나는 섹션 제목은 수집한 국내 화면에 없다.** 조건은 행 안의 라벨이나 값으로 내려간다(SM「취소 / 수업 시작 2일 5시간 30분 전까지」).

**[추론]** 섹션 제목은 훑어볼 때 닻 역할을 한다. 명사로 끝나야 "이 아래에 무엇이 있는지"가 한눈에 들어오고, 조건절 제목은 뒷말을 기다리게 만들어 미완성 문장처럼 읽힌다. 토스가 "모바일 앱을 쓸 때 읽지 않아요. 스캔하죠."(T8 Weed cutting)라고 쓴 것과 같은 이유다.

### 2.5 버튼

**주 버튼 (하단 CTA)**: 「예약하기」(CT, SM), 「지금 웨이팅하기」(CT), 「지금 자리선점」(TB), 「대기확정코드 입력하기」(TB), 「열차 조회하기」「선택하기」「결제하기」(SRT), 「내 대출 한도 확인」(TS), 「출석 체크하기」(C101), 「심부름 요청하기」「모임 입장하기」(KM), 「안내시작」(NM)
**보조, 짝 버튼**: 「예약취소 | 결제하기」(SRT 하단 2분할), 「미리보기 | 안내시작」(NM), 「닫기 | 해제하기」(KM 모달), 「취소 | 삭제」(MST 확인창)
**작은 행 버튼**: 「송금」「내역」(TS), 「예약하기」「대기하기」(BC 수업 행), 「자세히」(DG), 「팔로우」(CT), 「전화하기」(TB), 「설정」(SC), 「빈자리알림」(SNUTT `search_result_item_vacancy_button`)
**텍스트 링크**: 「전체보기 >」「더보기」(CT, BC), 「더 많은 매물 보기」「다른 알바 더보기」(DG), 「가게 전체 보기 >」(BM), 「전체 출석 현황 보기 >」(C101), 「예약 가능 날짜 찾기」(CT), 「포인트 받기」「140원 받기」「얼마 받을지 보기」(TS)
**사용자 발화형 선택지** (예외적 해요체): 알림톡 버튼 「[대기 취소할게요]」「[방문할게요]」(TB-W), 이용 방식 「먹고 갈게요」(CT)

**경향**
- 형태는 세 가지다. ① 명사+하기(예약하기, 결제하기) ② 동작 명사(송금, 내역, 예약취소) ③ 목적어+동사-기(포인트 받기, 가게 전체 보기). 주 버튼은 ①, 행 버튼은 ②가 많다.
- 해요체 버튼은 **사용자가 자기 의사를 말하는 선택지**일 때만 쓴다(「방문할게요」).
- 버튼 동사는 화면 제목이나 행 상태와 같은 단어를 쓴다: 「대기하기」 버튼 → 행 상태 「예약마감」; 「예약하기」 → 「예약완료」(BC). SNUTT도 「빈자리알림」 버튼 → 앱바 「빈자리 알림」.
- 번역 앱 통계: button 분류에서 noun/label과 `~기`가 SIG-i 71%, WP 80%, OM 90%, SNUTT 81%.

**[추론]** 버튼 라벨이 결과 화면의 제목이나 상태 배지와 같은 단어여야 "눌렀더니 그게 됐다"는 확인이 생긴다. 토스의 Predictable hint 원칙(「다음 화면을 예상할 수 있는 문장을 씁니다」, T8)과 같은 논리다.

**경향**: 제목은 "명사 + 완료/성공/변경" 또는 짧은 과거형 감탄(빈자리가 생겼어요!)이다. 본문은 **다음에 일어날 일 1문장**(알려드릴게요, 확인해보세요)이다. 제목과 본문은 다른 줄과 다른 위계에 둔다. **줄표로 한 줄에 잇는 예는 0**이다.

**경향**: 상황 1문장 + 해결 행동(문장 또는 버튼)이다. TE 원칙: 「지금 사용자가 어떤 상황에 처했는지(상황 설명) / 그것이 왜 발생했는지(이유) / 해결하려면 어떻게 해야하는지(해결책)」, 「~해야 해요라고 강요하는 듯한 말투보다, ~할 수 있어요라고 권유하는 말투를 쓰기도 하고요.」 TES: 「(우리 잘못인데) 에러 메시지에도 해요체를 적용해야 할까요?」에 「네!」라고 답한다.

## 3. 종결 형태 통계

### 3.1 번역 앱 8종 + SNUTT (key 이름으로 자리를 분류, `scripts/analyze.py`)
분류 규칙: key에 title/header/label이 있으면 title, button/action/confirm/cancel이면 button, pref/setting/toggle이면 setting, desc/summary/message/body/hint면 desc, toast/snackbar/copied/success면 toast, empty면 empty, error/fail이면 error. 종결은 마지막 어절로 판정했다(해요체 / 합니다·한다체 / ~세요 명령 / 질문 / ~기 명사형 / ~됨·함 / 명사·라벨).

| MM (8,231) | 78% | 65% | 53% / 14% | 45% / 26% | 0 / 402 |

(MST는 세부 출력 일부가 잘렸고 empty 71%, error 62%가 합니다체다.)

**읽는 법**
- 레지스터(합니다/해요)와 관계없이 **제목과 버튼은 55~90%가 명사, 라벨, `~기`다.** 이 부분은 "번역이라서"가 아니라 UI 자리의 성질로 보인다. 국내 SNUTT도 같다.
- 번역 앱은 설명과 오류를 **합니다체**로 쓰고, 국내 소비자 앱(TS, DG, TB, KM)은 **해요체**로 쓴다. SIG-A는 한 시트 안에서 「표시할 수 있습니다」와 「표시할 수 있어요」가 섞여 있다(`DonationPendingBottomSheet__your_*`). 번역 기여자가 여럿이라 생긴 불일치다.
- **"당신"**: WP 48, MM 25, BW 18, MST 15회이고 SIG-A 0, SNUTT 0, KM 0. 국내 앱은 "내 / 나의 / ○○님"을 쓴다(CT「나의 순서」, NM「그리니님을 위한」, TS「내 계좌」).
- **줄표로 문장 잇기** (`가 — 나` 패턴): MM 14, MST 1, 나머지 0. 국내 화면과 코드에서는 0.

## 6. 왜 그렇게 쓰는가 (전부 [추론])

1. **스캔 속도**: 앱바, 섹션, 배지는 '읽히는' 글이 아니라 '찾는' 표지다. 명사로 끝나야 눈이 단어 하나로 판단을 끝낸다. T8 「우리는 모바일 앱을 쓸 때 읽지 않아요. 스캔하죠.」
2. **공간**: 행, 배지, 버튼은 폭이 고정이라 종결어미 2~3자(~어요, ~습니다)도 비용이다. 그래서 조건은 「~ 시」, 기한은 「~까지」, 상태는 「~중 / ~완료」 한 음절 명사로 압축한다(BM, SM, BC).
3. **비교 가능성**: 목록 행과 라벨|값은 세로로 반복하며 비교한다. 문장이 섞이면 같은 정보가 행마다 다른 위치에 놓인다.
4. **버튼과 결과의 짝**: 버튼 「예약하기」 → 배지 「예약완료」, 버튼 「알림받기」 → 「알림받기 완료」(KM). 같은 명사를 공유해야 행동과 결과가 이어진다. 조건절 제목(「취소하면」)에는 짝지을 명사가 없다.
5. **위계 분리**: 제목(무엇이 됐나)과 본문(다음에 무슨 일)을 두 줄로 나누면 시선이 둘에 머문다. 줄표로 한 줄에 이으면 위계가 사라지고, 영어 em-dash 문체를 옮긴 것처럼 보인다.
6. **문장이 화면을 '설명서'로 만든다**: 상태 화면의 해요체 문장들은 스토어 설명문 문형(「~할 수 있어요」「~해요」)과 같다. 실제 앱은 이 문형을 스토어와 온보딩에 쓰고, 상태 화면에는 숫자와 명사를 쓴다(§3.2).
7. **말을 거는 해요체는 '사람이 말하는 순간'에만**: 푸시 제목, 말풍선, 빈 상태, 오류, 완료 본문, 사용자 발화형 선택지(「방문할게요」). 정보의 뼈대(제목, 행, 배지)는 명사로 둔다.

## 7. 반례와 주의 (규칙을 지나치게 일반화하지 않도록)

- **토스는 섹션 제목에도 해요 문장을 쓴다**: 「추천 상품으로 시작해요」, 대출 화면 제목 「1분 만에 대출 금리·한도 확인할 수 있어요」(TS). 브랜드 보이스가 강한 앱은 **화면의 주 제목 1개**를 문장으로 쓰기도 한다. 그래도 그 아래 섹션과 행은 명사다(「내 계좌」「최근 쓴 계좌」).
- **질문형 제목**: 「이웃들이 찾는 가게는?」(DG), 카드 「이번 달 화이팅하셨나요?」(BC), 「제주도, 렌터카 가격이 궁금하다면?」(KT). 추천이나 프로모션 카드에만 쓴다. 정보 섹션에서는 쓰지 않는다.
- **CT는 한 박스 안에서 해요체와 합니다체를 섞는다.** 레지스터 통일을 기계 규칙으로 걸기보다 "제목 해요 / 규정 합니다"처럼 자리별로 허용하는 편이 실제와 맞다.
- **토스는 오류에서 "~할 수 있어요"를 권장한다**(TE). "수 있어요" 전면 금지는 근거와 어긋난다.
- **KM은 당근 본앱이 아니라 MVP 실험 레포**이고, SM은 저해상 판독이며, 스크린샷은 스토어 홍보용으로 다듬은 화면이다. 실제 앱 최신 문구와 다를 수 있다.
- 번역 앱의 버튼과 라벨 형태는 좋은 예로 쓸 수 있지만, 문장(당신, ~하시겠습니까, 감탄 과장)은 반례로 다루는 게 안전하다.

## 8. 규칙 초안 (근거 ID 포함)

1. 앱바, 섹션 제목, 배지, 칩, 토글 라벨은 명사구로 끝낸다. 조건절(~하면 / ~나면 / ~할 때)은 금지. (§2.1, §2.2, §2.6, §2.7)
2. 큰 숫자는 [명사 라벨] + [숫자+단위]로 쓴다. 위치는 '번째', 고정 번호는 '번'. 주제 조사 문장(「내 ~은 N」)은 금지. (CT, TB)
3. 한 줄에 문장 하나. 줄표(—)로 문장 잇기 금지. 완료는 제목(명사+완료 또는 짧은 감탄)과 본문(다음 일 1문장)으로 나눈다. (KM, BC)
4. 행의 보조 줄과 메타는 문장 대신 "·"나 "|"로 이은 사실로 쓴다. 조건은 「~ 시」, 기한은 「~까지」, 시각과 상태는 「시각 + 예정/기준/등록」. (CT, BC, BM, SM, TB, SC)
5. 안내문은 덩어리당 1문장, 길어지면 불릿. 같은 말을 두 번 하지 않는다. (CT, T8)
6. "~할 수 있어요"는 기회 알림, 오류 해결책, 입력 제한, 가치 제안 제목 1곳에만 쓴다. 상태 화면의 반복 설명에는 쓰지 않는다. (§3.2, TE)
