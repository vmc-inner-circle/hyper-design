# 화면 종류별 구조 유형 — 국내 서비스 화면에서 묶기

> **2차가 기준이다.** 1차(아래 "1차" 절들)는 칸 순서 규칙으로 묶어 찾기형·진열형 경계가 흐렸다. 2차는 유형을 **첫 화면 주인공** 하나로 정의하고, 표본을 키워드 검색이 아니라 이름으로 정한 대표 앱으로 넓혔다.

## 2차 — 유형 = 종류 × ①첫 화면 주인공

| 속성 | 묻는 것 | 역할 |
|---|---|---|
| ① 첫 화면 주인공(`anchor`) | 머리줄·검색창·탭을 빼고 첫 화면에서 가장 큰 면적을 차지하는 것 | **유형을 정한다** |
| ② 반복 단위(`repeat`) | 아래로 반복되는 것(가로 줄·상품 격자·목록 행·큰 카드·순위) | 같은 유형의 변형 |
| ③ 마지막 행동(`exit`) | 하단 고정 버튼이 하는 일(구매·예약·요청·신청·없음) | 같은 유형의 변형 |

- 라벨러는 ①을 정해진 값에서 고르고, 유형은 `classify_v2.py`의 표로 기계적으로 정한다(칸 순서 규칙 없음).
- 찾기형·진열형을 가르는 질문: **맨 위 격자가 서로 다른 서비스(배달·포장·장보기 / 택시·대리·주차)인가, 같은 상품의 분류(상의·하의 / 한식·중식)인가.** 칸 어휘도 `서비스 격자`·`상품 분류 격자`로 나눴다.
- 홈 판정(스토어): 탭바 첫 칸이 선택된 화면, 또는 앱을 열면 바로 나오는 화면이 분명할 때만.

## 분류

`classify.py`가 칸 이름의 위치로 유형을 정한다(위에서부터 첫 규칙). **서로 다른 앱·사이트 3개 이상**에서 나온 것만 유형. `python3 classify.py [--src=store|mweb] [--miss]`.

규칙에서 배운 것:
- **맨 위 검색창은 유형을 가르지 않는다.** 웹·앱 홈 대부분이 검색창으로 시작한다 — 홈에서는 머리말로 보고 뺀다(처음 규칙은 이 때문에 진열형을 찾기형으로 빨아들였다).

## 읽을 때 주의

- **도메인보다 하는 일로 갈린다.** 한 앱이 탭마다 다른 유형이다(11번가: 찾기·진열·현황).
