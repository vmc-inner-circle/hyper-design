# 좋은 디자인의 기준 — VIBE PT 세션 근거

VIBE PT(최지운님, 2026-08-18 ~ 09-27) 세션 15개의 회의록·트랜스크립트와 외주 디자이너 미팅에서 실제로 나온 판단만 모았다. 일반론은 넣지 않는다. 각 원칙 아래 📏는 하네스가 측정할 수 있는 형태로 옮긴 것이다. 기준값은 [success-criteria.md](./success-criteria.md)에서 정한다.

## 1. 이해가 먼저, 예쁨은 나중

- "예쁘게 만드는 게 디자인의 업무가 아니에요. 이해할 수 있게 만드는 게" (OT)
- 화면마다 사용자에게 던질 **핵심 메시지 한 문장**을 먼저 정하고, 필요한 행동은 확실히 부각한다. (OT)
- "문구로 설명이 들어가는 게 최악이에요" — 설명이 필요한 UI는 구조가 틀린 것이다. (5회차)
- 하이파이 총평에서 유일하게 칭찬받은 것이 **정보 위계**였다. 가장 중요한 평가 요소. (sync2)

📏 화면당 주요 버튼 ≤ 1 · 도움말/툴팁/물음표 아이콘 0 · 평가 에이전트가 화면 목적을 한 줄로 맞히는가

## 2. 덜어내기 — 모든 섹션은 존재 이유를 증명해야 한다

- 섹션마다 "**누구를 위해, 언제** 보는가"가 불명확하면 지운다. 홈의 캘린더·통계 섹션이 이 이유로 제거됐다. (8회차)
- 홈은 다수 유저 기준. 열성 유저용 기능은 숨겨도 알아서 찾는다(당근의 글쓰기 버튼). (8회차)
- 같은 목적의 CTA·기능을 중복 배치하지 않는다. 탭 사이도 마찬가지. (8회차)
- 최신으로 유지하기 어려운 정보, 데이터가 빈약한 통계는 넣지 않는다 — "그냥 AI가 집어넣은 것 같아요". (8회차)
- 잠깐 지나가는 화면은 가볍게. (6회차)

📏 섹션별 {대상, 시점} 명시율 100% · 같은 목적 CTA 중복 0

## 3. 뻔한 게 이긴다

- "UX는 그냥 뻔할수록 좋은데… 독창적인 게 안 좋아요" (4회차)
- 토스·당근처럼 국내에서 데이터로 검증된 스타일에 맞춘다. (sync2)
- 한 화면에 한 가지 일(토스 원칙). 선택지는 적을수록 좋다. (5회차, 1회차)
- UI 패턴의 관례적 의미와 실제 동작이 일치해야 한다(날짜 스트립을 바꾸면 아래 영역이 바뀌어야 한다). (8회차)

📏 화면당 선택지 수 · 스텝당 입력 1~2개

## 4. 절제된 비주얼 = 토큰 일관성

- 흑백 기반에 **포인트 컬러 1~2개**, 채도만 정하고 나머지 노력은 UX에. (디자인 계약 미팅, 디자이너)
- "폰트가 따로 노는 느낌… 그레이스케일을 잘 못해서" — 회색 단계가 정돈돼야 엉성해 보이지 않는다. (10회차)
- 검수는 **토큰(색감·폰트 크기·라운드니스)과 일치하는지**만 본다. (디자이너 sync)
- 같은 역할이면 같은 스타일. 선택 상태는 **같은 모양에서 색만** 프라이머리로. (sync2)

📏 무채색 외 색상 ≤ 2 · 회색 단계 상한 · 토큰 밖 하드코딩 0 · 선택 상태에서 바뀌는 속성 = 색 1개

## 5. 빠진 상태는 결함, 넘치는 상태도 결함

- "로딩 없는 건 P0입니다" · 빈 결과·업로드 에러 누락은 P1. (sync2)
- 빈 상태는 결과가 있는 것처럼 보이면 안 되고, 행동을 유도해야 한다("그래프가 비어 있으면 기록해야겠다"). (디자인 계약 미팅)
- 0.5초 미만 대기에 로딩 화면을 띄우면 깜빡임이 된다. 긴 작업에만 진행률(1/30). (sync2)
- UI 부담이 큰 상태(숨김 등)는 뺀다. (8회차)
- 과거 교훈(#4): 게이트가 하한만 검사하자 화면당 상태 프레임이 7~8개로 불어났다. **상태는 규칙으로만 파생하고 상한을 둔다.**

📏 파생 규칙에 걸린 상태 누락 0 · 규칙에 없는 상태 0 · 화면당 default 포함 ≤ 3

## 6. 조작 부담 최소화

- "저만큼 작으면 핸드폰에서는 못 쓰거든요" — 터치 영역. (10회차)
- 뜻이 모호한 아이콘은 텍스트 라벨로("원본 보기"). (10회차)
- 문구는 구체적으로("저장" → "작성 중인 글을 임시 저장할까요?"), 친근한 용어로('이름' → '별명'). (sync2, 6회차)
- 이탈을 부르는 강제 고지 금지, 필수가 아닌 단계는 건너뛸 수 있게. (9회차, 6회차)

📏 터치 영역 ≥ 44px · 보편 아이콘이 아닌 아이콘 단독 버튼 0

## 7. AI 티는 감점

- 둥근 네모 남발 → "AI로 띡 돌린 느낌". (sync2)
- 목적 없이 끼워 넣은 섹션, 제목만 나열한 구조, 유형 식별이 안 되는 AI 생성 이미지. (8회차, 6회차, sync2)

📏 radius 적용 컨테이너 비율 상한 · 카드 중첩·동일 카드 반복 패턴 탐지

## 피드백 등급 (뱅크샐러드 P0~P3, sync2)

C단계 비평은 이 등급으로 낸다. **P0·P1이 0건이어야 통과**.

- **P0** — 있어야 할 것이 없음(결함). 예: 로딩 없음, 버튼을 눌렀을 때 갈 화면 없음.
- **P1** — 사용자 경험에 큰 영향. 예: 선택 상태에 프라이머리 미적용, 결과 없음 화면 없음.
- **P2** — 편의·심미 개선. 예: 아이콘 품질, 버튼이 과하게 큼.
- **P3** — 취향 차이.

## 8. 예쁨의 근거는 토큰 세 가지 (9/30 싱크, 디자이너 결과물 분석)

- **컬러**: 프라이머리 버튼 색이 눈에 편하고 잘 들어온다. 글자색은 순검정 대신 눈이 편한 짙은 색.
- **타이포**: 강조할 것은 확실히 크고 굵게, 강조 안 하는 문구는 더 작고 얇게. 폰트마다 어울리는 크기·굵기·색 조합이 다르므로 **폰트별로 토큰 세트**가 필요하다.
- **스페이싱**: 요소 사이가 떨어져 있어 보기 편하다. AI 기본 출력은 "다닥다닥 붙어서 피곤하다".
- "3D 아이콘이 없어서가 아니다 — 기본 폰트에 도형만 그렸는데도 예뻤다."

## 9. 유저플로우는 문서다 (9/30 싱크)

- 모든 화면을 화살표로 잇지 않는다. **주요 분기만** 화살표.
- 사용자가 밟게 될 **오류·성공 상태**는 반드시 그린다.
- 온보딩·홈·피드처럼 **큰 단위로 그룹핑**.
- 화면 아래에 **관련 정책(비즈니스 로직)**을 텍스트로: "최대 10장, 영상 불가", "X를 누르면 상세 작성부터". 화살표로 그리기 번거로운 흐름·엣지 케이스도 여기에.
- 프로토타입은 8단계를 다 눌러봐야 이해된다 → 한 장에 흐름이 보이는 보드가 더 나은 의사소통 수단. 단, **보드 자체가 어렵거나 복잡하면 안 된다**.

📏 [success-criteria §9](./success-criteria.md)

## 10. 하단 고정 CTA는 "확정"에만 (10/1 리뷰)

판단 질문: **이 화면에서 할 일이 딱 하나이고, 누르면 무언가 확정되거나 다음 단계로 넘어가는가?**

- 쓴다: 입력·선택 단계(다음·저장·완료), 확정 직전 확인(보내기·확정하기), 한 가지 결정을 하러 들어온 화면(함께하기·답 보내기), 완료 화면(확인)
- 안 쓴다
  - **탭 첫 화면(홈·목록 허브)** — 여러 목적이 섞인 둘러보기 화면. 탭바와 겹치면 하단이 가려진다.
  - **"~보기" 같은 이동** — 링크다. 머리글의 작은 링크나 누를 수 있는 행으로.
  - **목록에 추가** — 목록 끝 "+ 추가" 행, 앱바 + 아이콘. "열성 유저 기능은 숨겨도 찾아간다"(8회차).
  - **상황에 따라 생기는 할 일**(예: 보낼 소식 2건) — 해당 블록 안의 인라인 버튼으로, 할 일이 있을 때만.
- 원인 기록: "화면당 주요 버튼 **최대** 1개"라는 상한만 있자 모든 화면에 하나씩 붙었다. 상한이 아니라 **쓰는 조건**을 규칙으로 둔다.
