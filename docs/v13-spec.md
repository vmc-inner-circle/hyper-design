# v13 최종 설계 — 명세를 끝까지, 도메인을 보이게

## 0. 배경과 목표

외부 비공개 PRD(사진 중심 기록·커뮤니티 앱, 기획 브리프 + 기능명세서 34KB)에서 v12.1이 바닐라에 1/5로 졌다. 같은 PRD의 실제 디자이너 결과(100장+)와 비교한 차이: ① 명세 흐름·예외 상황의 양 ② 실제 같은 이미지 ③ 도메인에 맞는 색 ④ 도메인 시각물. 방향(여정·시기별 홈·정책 메모)은 디자이너와 같았다.

**v13 합격 기준**

| PRD | 기준 |
|---|---|
| 비공개 명세서형 | 바닐라 대비 ≥ 3/5 · 루브릭 ≥ 3.5 · P0 0 · 명세 목록 커버 100% · 글자만 든 사진 자리 0 |
| 새 공개 명세서형 | 바닐라 대비 ≥ 3/5 · P0 0 · 명세 목록 커버 100% |
| 가족여행·청첩장(브리프) | 회귀 없음: 루브릭이 v12.1보다 0.3 넘게 낮지 않음 · P0 0 |
| 전부 | 하네스 시간 ≤ 15분 · 개입 ≤ 4회 · 캔버스 상호작용 테스트 통과 |

**범위**: ① 명세 목록 ② 규칙 → 상태 ③ 색 시드 ④ 이미지 ⑤ 파운데이션 공통 부품 ⑥ 캔버스 탭·드래그 ⑦ 평가 세트. 앱 전용 `d-` 부품은 v14.

## 2. 명세 목록 (화면 수 상한 폐지)

### 산출물 `out/spec_inventory.json`
```json
{"mode": "spec",
 "items": [
  {"id": "S12", "kind": "screen", "name": "설문 1/3 — 시작 동기", "quote": "PRD 원문 한 줄", "covered_by": ["onb-survey-1"]},
  {"id": "R4", "kind": "rule", "name": "같은 날 찍은 사진만", "quote": "…", "target": "photo-pick", "state": "error"},
  {"id": "F7", "kind": "feature", "name": "필터 초기화", "quote": "…", "covered_by": ["feed"]},
  {"id": "S20", "kind": "screen", "name": "챌린지", "quote": "…", "decision": "D3"}]}
```
- kind: `screen`(PRD가 화면·페이지로 부른 것) · `step`(온보딩 1/5처럼 단계) · `feature`(화면 안 요소) · `rule`(데이터 규칙·제약).
- **추출은 서브에이전트**(PRD 원문 + 위 스키마만 받음). 메인은 병합 때 너무 잘게 쪼갠 screen을 합친다(같은 화면의 탭·섹션은 feature로).
- **mode**: screen+step ≥ 15 → `spec`, 아니면 `brief`.
  - brief: 지금처럼 여정에서 10~16장.
  - spec: screen·step은 전부 화면. 빼려면 `decision`(decisions.json의 cut/later, PRD 출처면 ask).
- `setup_out.py`가 PRD를 `out/prd.md`로 복사.

### selfcheck 추가
- 모든 quote가 `out/prd.md`에 부분 문자열로 존재(공백 정규화) — 지어낸 목록 방지
- screen·step: covered_by 화면 존재 또는 decision 존재(PRD 출처 cut/lighten이면 ask)
- spec 모드에서 PRD 출처 cut이 3개 초과면 실패(과삭제 신호)
- feature: covered_by 화면 존재

## 3. 규칙 → 상태 (예외 상황)

### 상태 종류
| 상태 | 언제 | 파생 근거 |
|---|---|---|
| empty | 목록 + 첫 사용 | traits.list_first_use |
| error | 폼 · 규칙 위반 | traits.form · rule(state=error) |
| done | 밖으로 내보냄 · 한 번 누르는 요청 | traits.shares |
| **confirm** (신규) | 되돌릴 수 없음 · 중복 경고 대화상자 | rule(state=confirm) |
| **progress** (신규) | 사용자가 지켜봐야 하는 긴 작업 | traits.long_task |

`loading`·`success`는 계속 금지.

### `scripts/expand_states.py` (신규)
- 입력: screens.json(기본 화면) + spec_inventory.json(rule)
- 각 기본 화면의 상태 = traits 파생 ∪ 그 화면을 target으로 하는 rule의 state
- 같은 화면·같은 상태에 rule이 여럿이면 **한 상태 화면으로 묶고** 나머지 rule은 `policies`에 한 줄씩 추가
- screens.json에 `<id>--<state>` 항목을 자동 추가(파일 경로·그룹·purpose 상속, `rules: ["R4","R9"]`)
- 화면당 상태 > 3이면 실패 출력 → 메인이 rule을 정책 문구로 내린다
- 메인은 상태 항목을 손으로 쓰지 않는다(시간 절약 + 일관성)

### 검사
- selfcheck: rule마다 상태 화면이 있거나 policies에 rule id가 인용됨
- score.py `ALLOWED`에 confirm·progress 추가, progress는 long_task 화면에만
- judge 체크리스트: "confirm 대화상자가 되돌릴 수 있는 행동에 쓰였다(P1)"

## 4. 색 — 라이브러리 우선, 맞는 게 없으면 시드

### 구동 시 (`palette_pick.py`)
1. 라이브러리 채점(지금 그대로).
2. **custom 모드 조건**: 1위가 도메인 일치 없음 + 성격 태그 겹침 ≤ 1.
3. custom이면 `seeds.json`을 같은 방식(도메인·태그·감정 온도)으로 채점 → 1위 시드로 `derive.py --brand <hex> --tone <회색 온도>` → `tokens-seed-<slug>.css`. 대안 2개는 라이브러리에서(색상각 ≥ 40°).
4. palettes.json의 why에 "라이브러리에 <도메인>이 없어 시드 <이름>으로 만듦" 기록.

### 빌드 시 1회 — 시드 시트
1. **후보 수집**(50~60개): 라이브러리 10곳 브랜드색 + 국내외 서비스 30~40곳 웹 CSS에서 브랜드색(`palette_scrape.py --brand-only`, 대상 목록 `foundation/palettes/seed_sources.txt`: 뷰티·웰니스·교육·커뮤니티·예약·음식·금융 제외) + 디자이너 결과물 브랜드색. 출처·도메인 라벨.
2. **자동 거르기** → 24개 안팎:
   - 스케일 브랜드 단계 흰 글자 대비 ≥ 3
   - OKLCH 채도 C ≥ 0.08(탁함 방지), 명도 L 0.45~0.75
   - 오류 빨강과 색상각 25° 이내 제외
   - 서로 ΔE2000 < 10이면 하나만
3. **시트 렌더링** `scripts/seed_sheet.py` → `foundation/palettes/seed-sheet.png`: 시드마다 한 칸 = 채운 버튼 · 선택 칩 · 배지 5종 · 틴트 블록 · 목록 행 · 회색 바탕. 칸 아래 번호·이름·출처.
4. **사람 승인**: 시트를 보고 뺄 번호를 답한다. 승인된 것만 `seeds.json`.
5. `seeds.json`: `{slug, name, hex, tone: warm|neutral|cool, tags[], domains[], source}`.

## 5. 이미지

### 판단 — `screens.json` 최상위 `photo_centric`
PRD에서 사진·이미지가 사용자가 만들거나 보는 **핵심 콘텐츠**면 true. false여도 사람·장소·음식 사진 자리가 있으면 이미지 에이전트는 돈다(자리 수가 적을 뿐).

### 이미지 서브에이전트 (1단계, 빌드와 겹쳐 진행)
1. **자리 목록** `out/image_slots.json`: `{slot, screens[], what, ratio: "3:4|1:1|16:9", kind: "photo|drawing", query_en, query_ko}`
2. **자리표시 즉시 생성**: 자리마다 `assets/photos/<slot>.jpg`(또는 `assets/domain/<slot>.svg`) 경로에 중립 회색 자리표시 파일을 먼저 쓴다 → 빌드 에이전트는 경로만 알면 된다(기다리지 않음).
3. **photo**: Openverse 검색(license=cc0,pdm,by · 짧은 변 ≥ 600px · 자리당 후보 6장) → 축소본을 내려받아 **직접 보고** 1장 선택 → 비율대로 잘라(가운데 기준, 필요시 얼굴 흐림) 자리표시 파일을 교체 → `out/credits.json`.
4. **drawing**: 도식·사물·연속 변화는 SVG(고정 색 허용, 얼굴 금지, 글자 라벨 금지).
5. **시간 상한 3분**: 넘으면 남은 photo 자리는 drawing으로 대체하고 종료.
6. 검색 결과는 `~/.cache/hd-openverse/`에 캐시(같은 검색어 재사용, 호출 한도 대비).

### 파운데이션 부품
`.photo`(aspect-ratio 변수 · radius · object-fit cover · 회색 바탕) · `.thumb`(56/72px) · `.photo-grid`(3열, 간격 2px).

### 검사
- selfcheck: `.photo` 안에 `<img>` 없이 글자만 → 실패 / credits.json에 없는 `assets/photos/*` → 실패 / 라이선스 ∉ {cc0, pdm, by} → 실패 / photo_centric인데 이미지 0 → 실패
- 캔버스 하단: "사진 출처" 접기(작가 · 라이선스 · 링크)
- git: `loop/results/*/assets/photos/`는 .gitignore(credits로 재현)

## 7. 캔버스 — 탭 3개 + 모드 없는 드래그

### 구조 (템플릿 `scripts/canvas_template.html`, 빌드 시 1회 작성)
```
header : 제목 · [Screens | Foundation | Components] · 팔레트 색 점 3 · [전체 보기 · 배율%]
stage  : Screens 판(transform: translate + scale)
panes  : out/foundation.html · out/components.html (처음 열 때 iframe 로드)
modal  : 화면 크게 보기(390×844 실제 iframe, 스크롤·링크 동작)
```
- `build_canvas.py`는 데이터(screens.json·decisions·story·palettes·credits)를 템플릿에 끼워 넣고, `foundation.html`·`components.html`을 생성. **AI 시간 0, 스크립트 < 1초.**

### 이동·확대
- 포인터: pointerdown → 4px(터치 8px) 넘게 움직이면 이동, 아니면 클릭. 화면 카드 위에는 투명 덮개를 둬서 iframe이 이벤트를 먹지 않게.
- 휠 = 이동, Ctrl/⌘+휠·핀치 = 확대(0.25~1.5, 포인터 위치 기준), "전체 보기" = 모든 줄이 들어오게. 첫 배율 0.72.
- 카드 클릭 → 크게 보기 모달(Esc·바깥 클릭으로 닫기).
- 화면 로드: 보이는 카드만 iframe src를 넣는다(이동·확대 후 100ms 묶어서 계산).

### Foundation 탭
- 색: 역할 30개를 묶음(배경 · 글자 · 브랜드 · 의미색 · 선·그림자)으로. 칸마다 쉬운 이름("버튼 색") 크게, 토큰 이름·값 작게. 값은 브라우저가 tokens.css에서 읽음 → 팔레트 전환 즉시 반영.
- 글자 단계(실제 크기로 "가나다 Aa"), 여백·모서리·그림자 견본.

### Components 탭
- `foundation/specimens.html`(부품별 섹션, `data-key="btn"` 등)에서 **화면들이 실제로 쓴 클래스**의 섹션만 골라 생성. 상태별 모습(기본·눌림·비활성·선택·오류) 포함. 배지는 이 결과물의 배지 표(뜻→색)로.

### 기준·검사 변경
- success-criteria §9: "버튼·토글 ≤3, 조작 모드 0" → **"조작 그룹 ≤ 3(탭 · 팔레트 · 보기), 모드 전환 0"**
- score.py: `data-group` 속성 그룹 수 ≤ 3, 모드 토글 0
- **상호작용 테스트**(score.py, Playwright): 빈 곳 200px 드래그 → 판 이동 / 카드 클릭 → 모달 열림 / Foundation 탭 → 색 칸 ≥ 20 / Components 탭 → 섹션 ≥ 5 / 팔레트 점 클릭 → Foundation 브랜드 칸 값 변경

## 8. 평가 세트

| PRD | 형태 | 위치 | 비교 |
|---|---|---|---|
| 가족여행 | 브리프 | 저장소 | 바닐라 · 정답지 |
| 청첩장 | 브리프 | 저장소 | 바닐라 |
| 필라테스·요가 예약(신규) | 명세서 | 저장소 | 바닐라 |
| 비공개 기록 앱 | 명세서 | `~/hd-private/` | 바닐라 · 디자이너 캡처 |

- **신규 PRD 작성**: 하네스 문서를 보지 않은 별도 에이전트에 "외주를 맡기는 클라이언트 PM" 역할만 준다. 지정하는 건 분량(15~25KB)과 목차(서비스 개요 · 문제 · 타깃 · 기능 목록 · 화면별 명세 약 25개(요소·정책) · 데이터 규칙 · 논의점)뿐. 디자인 방향·색·화면 수 언급 금지. 사용자가 훑어본 뒤 확정.
- **디자이너 비교**: judge에 디자이너 캡처를 함께 주고 "범위 · 예외 · 시각" 1~5점 추가(비공개 PRD만).
- **채택 규칙**: 세트 평균 루브릭이 이전보다 0.3 넘게 낮지 않고, 어느 PRD에서도 새 P0가 없을 때.
- **비공개 보호**: `~/hd-private/`(PRD·결과·캡처), 로컬 pre-commit 훅이 키워드 목록(`~/hd-private/.keywords`)을 staged diff에서 찾으면 커밋 차단.

가능성·영향: 상/중/하. "신호"는 이 리스크가 터졌다고 판단할 기준, "비상 조치"는 그때 할 일.

### 가장 큰 리스크 3개
1. **R2 브리프 회귀** — 이번 변경 대부분이 명세서형을 위한 것이라 기존 강점을 깎을 수 있다. mode 분기와 회귀 기준으로 막는다.
2. **I1 스톡 품질** — Openverse만으로는 "실제 같은 사진"이 안 나올 수 있다. 첫 구동에서 선택 실패율을 보고 Pexels 키 여부를 다시 정한다.
3. **T1 시간** — 명세 모드 + 이미지 + 상태 확대가 겹치는 첫 구동에서 15분을 넘을 수 있다. 단계별 시간을 기록해 숫자로 대응한다.
