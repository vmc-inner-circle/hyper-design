# v13 설계 — 명세를 끝까지, 도메인을 보이게

배경: 외부 비공개 PRD(사진 중심 기록·커뮤니티 앱, 기획 브리프 + 기능명세서 34KB)에서 v12.1이 바닐라에 1/5로 졌다. 같은 PRD의 실제 디자이너 결과(100장+)와 비교한 차이: ① 명세 흐름·예외 상황의 양 ② 실제 같은 이미지 ③ 도메인에 맞는 색 ④ 도메인 전용 시각물. 방향(여정·시기별 홈·정책 메모)은 디자이너와 같았다.

원칙: 두 PRD(가족여행·청첩장)에서 얻은 규칙은 유지하되, **"PRD가 짧은 브리프인가, 화면을 나열한 명세서인가"** 에 따라 범위 규칙을 나눈다.

---

## 1. 명세 목록 — 화면 수 상한 폐지

**무엇을**
- 1단계 맨 앞에 `out/spec_inventory.json`을 만든다.
  ```json
  {"mode": "spec|brief",
   "items": [{"id": "S12", "kind": "screen|step|feature|rule", "name": "설문 1/3 — 곱슬 여정 시작 동기",
              "quote": "PRD 원문 그대로 한 줄", "covered_by": ["onb-survey-1"], "decision": null}]}
  ```
- `mode`: screen·step 항목이 15개 이상이면 `spec`(명세 모드), 아니면 `brief`(지금처럼 여정에서 화면을 끌어냄).
- 명세 모드: 목록의 screen·step은 전부 화면이 된다. 빼려면 `decision`에 decisions.json id(cut/later + ask)를 적는다.
- 화면 수 규칙: brief 10~16장 / spec은 목록대로(상한 없음).
- 빌드 서브에이전트 수 = ceil(화면 수 / 5), 최대 8. 상태 화면은 기본 화면을 복사해 바뀐 요소만 고친다(같은 에이전트).
- `setup_out.py`가 PRD를 `out/prd.md`로 복사.

**검사 (selfcheck)**
- 모든 item의 `quote`가 `out/prd.md`에 실제로 있는가(지어낸 목록 방지)
- screen·step item은 `covered_by`의 화면이 존재하거나, `decision`이 있고 그 결정이 `ask: true`
- 명세 모드에서 PRD cut이 3개를 넘으면 실패 — 묻는 한도(3개)를 넘는 삭제는 과삭제 신호로 보고 되살린다

**리스크**
- 목록을 너무 잘게 쪼갬(문장마다 화면) → 화면 부풀리기. 대응: rule·feature는 화면이 아니라 상태·요소로 덮는다. screen·step만 화면.
- 시간 15분 초과. 30~40장이면 빌드 병렬을 늘려도 15~20분 예상. → **성공 기준을 brief 15분 / spec 25분으로 나눌지 결정 필요.**
- 캔버스 복잡도: 40장+는 화이트보드 단순성(§9)과 충돌. 대응: 한 줄=한 흐름 유지, 상태 화면은 기본 화면 아래로 접어 두고 펼치기 1개(조작 요소 3개 이내 유지).
- 덜어내기 원칙과 긴장: 명세 모드에서는 "빼기"가 아니라 "가볍게 그리기"로 덜어낸다(같은 화면 재사용·시트로 처리).

## 2. 규칙에서 예외 상황 만들기

**무엇을**
- `kind: rule` 항목(날짜 순서, 같은 날 사진만, 중복 기록, 권한 거부, 업로드 실패…)은 `covered_by`에 상태 화면 `<id>--<state>`를 적는다.
- 상태 종류 확장: 기존 `empty·error·done` + **`confirm`**(되돌릴 수 없는 행동·중복 경고 대화상자) + **`progress`**(긴 작업 — `traits.long_task: true`인 화면만).
- `loading`·`success`는 여전히 금지. `progress`는 "사용자가 기다리는 것을 봐야 하는 긴 작업"(사진 여러 장 업로드·외부 처리)에만.
- 비슷한 규칙은 상태 하나로 묶는다(예: 날짜 순서 오류 4종 → 가장 대표적인 1장 + 정책 한 줄에 나머지).

**검사**
- selfcheck: rule 항목마다 상태 화면이 있거나 `policies`에 인용되어 있다
- 화면당 상태 ≤ 3 (기존 게이트 유지)
- score.py ALLOWED에 confirm·progress 추가, progress는 long_task 화면에만

**리스크**
- 상태 과잉 정의(사용자 초기 우려). 대응: PRD에 **인용된** 규칙만 상태를 만들 수 있다. 하네스가 떠올린 예외는 정책 문구로만. 화면당 3개 상한.
- confirm 대화상자 남발 → "되돌릴 수 없음·중복"일 때만, 나머지는 같은 요소 오류.

## 3. 색 — 라이브러리에 맞는 게 없으면 시드에서 만들기

**무엇을**
- `palette_pick`이 기본값 점수를 보고 판단: 도메인 일치가 없고 성격 태그 겹침 ≤1이면 **custom 모드**.
- custom 모드에서 하네스는 자유 hex가 아니라 **검증된 브랜드 시드 목록**(`foundation/palettes/seeds.json`, 20~24색)에서 고른다. 시드마다 이름·분위기 태그·어울리는 도메인·흰 글자 대비 확인값. 예: 올리브(자연·성장·뷰티), 테라코타(따뜻함·수공예), 플럼(감성·뷰티), 딥틸(건강·차분)…
- 시드 → `derive.py --brand`로 토큰. 대안 2개는 라이브러리에서(색상각 40° 이상).
- 라이브러리 확장(빌드 시 1회): 뷰티·웰니스·커뮤니티·교육 3~5곳 추가(`palette_scrape.py` + 사람이 캡처 보고 브랜드 확정).

**리스크**
- 만든 팔레트가 실제 서비스 팔레트보다 덜 정돈됨(회색 계열 불일치) → 시드마다 회색 온도(따뜻·중립·차가움)를 같이 지정.
- 탁한 색 재발(v8 주황 사고) → 시드는 미리 렌더링 시트로 사람이 한 번 승인한 것만.
- 시드 목록 자체가 내 취향 편향 → 디자이너 결과·실제 앱 색에서 역으로 뽑는다.

## 4. 이미지 — 빈 사진 박스 금지

**무엇을**
- screens.json 최상위 `"photo_centric": true`(사진·이미지가 핵심 콘텐츠인 앱).
- true면 1단계에서 **이미지 서브에이전트 1개**를 병렬로: `out/assets/domain/*.svg` 6~10개.
  - 사진 대체(3:4, 1:1): 도메인 소재의 질감·실루엣(예: 곱슬 질감, 뒷머리, 제품 병) — 글자 라벨 금지
  - 제품·사물 썸네일, 도메인 도식(예: 곱슬 타입 2A~4C)
  - 색은 고정 hex 허용(사진은 브랜드 색이 아니다 — Fluent 일러스트와 같은 예외). 사람 얼굴은 그리지 않는다(뒷모습·크롭).
- 부품 추가: `.photo`(aspect-ratio·radius·object-fit), `.thumb`, `.photo-grid`.

**검사**
- selfcheck: `.photo` 안에 이미지 없이 글자만 있으면 실패("사진 1" 박스 방지)
- photo_centric인데 assets/domain이 비었으면 실패

**리스크**
- SVG 그림이 싸구려·AI 슬롭처럼 보임(그라데이션 금지 규칙과 충돌) → 그라데이션은 assets/domain 안에서만 허용, 평가자 체크리스트에 "이미지가 장식인가 내용인가" 추가.
- 시간 +1~2분(병렬이라 대부분 숨겨짐).
- 실제 사진(무료 스톡)은 라이선스·네트워크·얼굴 문제로 이번엔 하지 않는다.

## 5. 도메인 전용 부품 (v13에서는 설계만, 구현은 결과 보고)

- `out/domain.css`에 `d-` 접두사 클래스 최대 3개, 값은 `var(--*)`만. screens.json `"domain_parts": [{"class": "d-curl-range", "why": "…"}]`.
- selfcheck: hex 0, 클래스 ≤3, 선언된 것만, 화면에서 1번 이상 사용.
- 리스크: 파운데이션 우회 통로가 됨 → 상한 3개 + 이유 필수 + 평가자가 일관성 항목에서 감점.

## 6. 평가 세트 — 과적합 방지

- PRD 4~5개: 가족여행(brief)·청첩장(brief)·외부 비공개 PRD(spec, **저장소 밖** `~/hd-private/`) + 새 공개 PRD 1~2개(명세서형·다른 도메인, 직접 작성).
- 디자이너 결과가 있으면 평가자에게 캡처를 같이 주고 "디자이너 대비" 3항목(범위·예외·시각) 1~5점(§10 구현).
- 채택 규칙: 세트 평균 루브릭이 0.3 넘게 내려가지 않고, 어느 PRD에서도 새 P0가 없을 때만 채택.
- 비공개 유출 방지: 결과·PRD는 `~/hd-private/`에만. 로컬 pre-commit 훅이 비공개 키워드 목록을 grep해 커밋 차단.

**리스크**
- 비용·시간: PRD 5개 × 구동+평가 ≈ 반복 1회 40~60분, 세션 한도(v6 때 경험).
- 평가자 노이즈 ±0.3 → PRD 수를 늘리는 것으로 일부 상쇄, 같은 버전 2회 구동은 큰 변경 때만.
