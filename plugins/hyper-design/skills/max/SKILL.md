# hyper-design:max — 2차: 상태·예외까지

**경로**: 이 스킬을 불러올 때 표시되는 Base directory의 `../../core`가 공용 폴더다. 맨 처음 `SK=$(cd "<Base directory>/../../core" && pwd)`, 1차 지시문은 `<Base directory>/../go/SKILL.md`.

## 0. 어디서 시작하나
- `out/screens.json`이 있고 `"stage": "go"`면 → **1차는 끝났다. 바로 2차로.** 첫 줄: "1차 위에 상태 화면을 더할게요. 10분쯤 걸려요."
- `out/screens.json`이 없으면(PRD를 받음) → 첫 줄: "처음부터 끝까지 만들게요. 25분쯤 걸려요." 그리고 **1차 지시문(go/SKILL.md)을 그대로 따른다** — 단, 1차의 "끝 — 마지막 메시지"는 쓰지 않고(중간에 `[[DONE]]` 금지) 2차로 이어 간다. 1차에서 PRD 요구사항 확인(`[[ASK]]`)이 필요하면 그때는 턴을 끝내고, 답을 받으면 1차 → 2차를 이어 간다.
- `"stage": "max"`면 이미 끝났다 — 캔버스 경로만 알려 주고 무엇을 고칠지 묻는다.

## 1. 상태 펼치기 (1분)
- `python3 $SK/scripts/expand_states.py out --stage max` → 오류(`error`)·확인 대화상자(`confirm`)·빈 상태(`empty`)·진행 중(`progress`)·규칙 상태가 screens.json에 추가된다. 화면당 상태 2개 초과 오류가 나면 해당 규칙을 정책 문구(`policy`)로 내리고 다시.
- 새로 생긴 상태 화면 목록(`state_of`·`state`·`rules`)을 흐름(group)별로 묶는다.

## 2. 병렬 빌드 (5분)
- 빌드 서브에이전트 **ceil(상태 화면 수 / 5)개(최대 8)를 한 메시지에**. 같은 흐름끼리 묶는다.
- 각 에이전트에게: `$SK/references/principles.md` 전문, `$SK/foundation/COMPONENTS.md` 전문, `out/journey.md`의 사실 표, 맡은 상태 항목(규칙 원문 인용 포함), 그리고 아래 규칙:
  - **기본 화면 파일을 복사해 바뀐 부분만 고친다.** 구조(제목 위치·블록 묶음·사진)는 그대로.
  - **상태가 바뀌면 그 상태와 모순되는 정보는 지운다**(예: 이미 시작돼 취소할 수 없는데 "취소하면 7회→6회" 안내가 남아 있으면 안 된다).
  - **오류 이유는 첫 화면(스크롤 없이)에 보인다** — 문제 칸 바로 아래 또는 맨 위. 해결 행동이 주 버튼, 같은 목적 버튼을 하나 더 붙이지 않는다.
  - `error`: 같은 요소에서 문제 칸만 바뀐다(경고 아이콘 + 문구). `confirm`: 바텀시트 대화상자 — 되돌릴 수 없는 행동·중복 경고에만, 위험한 확인은 오류 색 글자. `empty`: 첫 사용 — 다음 행동 하나. `progress`: 진행률·남은 개수·취소/백그라운드 안내.
  - 1차 화면은 고치지 않는다(사용자가 이미 봤다). 상태 화면으로 가는 링크가 필요하면 그 한 줄만 추가한다.

## 3. 검증·수정 (3분)
한 메시지에서 동시에(포그라운드): `build_canvas.py out` · `selfcheck.py out` · `audit.py out --shots out/.shots` + 사실 대조 서브에이전트 1개. 비평 체크리스트는 `$SK/references/checklist.md`. 수정은 1회, 상태 화면 위주로 흐름별 병렬.

## 끝 — 마지막 메시지
- 무엇을 더했는지 2줄(상태 화면 수, 대표적인 예외 순간 2~3개)
- (1차부터 했다면) 1차 마지막 메시지의 내용(핵심 한 문장, 화면 수, 기본 색과 이유, 뺀 것은 캔버스 맨 위)도 함께
- 남은 ❌ 항목(있으면)
- 마지막 줄: `[[DONE out/index.html]]`
