# 빌드 에이전트 지시문 — 묶음 파일 맨 앞에 그대로 들어간다

`scripts/pack.py`가 이 글을 각 빌드 에이전트의 묶음 파일(`out/packs/<n>.md`) 1절로 붙인다. 빌드 규칙을 고칠 때는 이 파일을 고친다.

- **이 묶음 파일을 끝까지 읽는다** — 원칙·부품·사실 표·맡은 화면 항목·관례·명세·이미지 경로가 다 들어 있다. 맨 끝의 확인 문구를 결과 보고 **첫 줄**에 그대로 쓴다(메인이 묶음을 읽었는지 이것으로 확인한다).
- 묶음에 없는 것만 더 연다: PRD(`out/prd.md`)의 맡은 화면 절(화면 안 요소·동작은 명세 목록에 없다), 모범 답안(구조만 참고), 근거 시트. 다른 에이전트의 화면 파일은 열지 않는다(상태 화면의 기본 화면만 예외).
- 각자 **자기 파일만** 쓴다: `out/screens/<id>.html` — COMPONENTS.md의 뼈대 그대로(`../tokens.css`·`../components.css`·`../palette.js`, 일러스트 `../assets/fluent/<이름>.svg`). 갈래·이동은 실제 `<a href>`로 잇는다.
- **부품은 COMPONENTS.md의 판단 질문으로 고른다** — 화면마다 "탐색·진열·판촉" 절의 질문에 답해 예인 부품을 쓴다. 목록 행·흰 블록만으로 모든 화면을 짜지 않는다(질문이 예인데 행으로 대신하면 실패). 화면을 채우려고 쓰지도 않는다.
- **화면 유형대로 짠다**: 맡은 화면에 `archetype`이 있으면 묶음의 유형 행(첫 화면 주인공·부품·아래로)대로 — 스크롤 전 첫 화면에서 가장 큰 면적은 그 주인공이 차지하고, 주인공 요소에 `data-anchor`를 단다(audit가 잰다). 사람 카드의 알고 싶은 것은 그 주인공 자리에 담는다. 원칙 1의 핵심 메시지 머리글(지금 상황 한 문장)은 대표 콘텐츠형·피드형이 아니면 주인공 위에 그대로 둔다 — 주인공보다 커지면 안 되는 건 그 사이에 끼는 아바타 줄·안내 띠다.
- **사람 카드**: 맡은 화면을 쓰는 사람의 알고 싶은 것(`at`이 그 화면인 것)은 첫 화면에서 그 답을 가장 크게, 말투는 그 사람의 마음에 맞춘다. 질문마다 블록을 만들어 질답지로 만들지 않는다 — 질문 문장을 제목으로 달지 않고, 답은 데이터(사진·이름·기간·숫자)의 자리와 크기로 준다.
- **사실은 사실 표에서만**: 표에 없는 날짜·숫자·상태를 지어내지 않는다. 같은 대상은 모든 화면에서 같은 값.
- **시장 관례는 구조만 참고**, 문구·그림·색은 베끼지 않는다. 피할 것(리뷰 불만)이 맡은 화면에 해당하면 정책·문구로 막는다.
- **명세 항목**은 그 화면에 보이게 한다. 상태 화면은 그 상태의 규칙(`rules`·명세 rule)이 보이는 모습으로.
- **이미지**는 묶음에 적힌 그 화면의 경로(`../assets/photos/<slot>.jpg`)만 쓴다 — 자리표시 상태여도 그대로 둔다(선택 에이전트가 같은 파일을 교체한다). drawing 자리는 선과 토큰 색으로 직접 그린다.
- **배지·강조·판촉**: 배지는 묶음의 `badges` 표에 있는 이름·색만, 강조 부품은 `accent`가 있을 때만, 배너·띠 배너·쿠폰·남은 시간은 `promos`에 선언한 것만.
- **상태 화면은 기본 화면 파일을 복사해 바뀐 부분만 고친다** — 같은 화면의 두 모습이 구조(제목 위치·블록 묶음·사진 크기)가 달라지면 안 된다. 기본 화면을 먼저 쓰고 상태 화면을 쓴다. 상태 화면에 기본 화면과 같은 목적의 버튼을 하나 더 붙이지 않는다(해결 행동이 주 버튼).
- 검사(selfcheck·audit)는 메인이 돌린다. 화면 추가·삭제, screens.json·스크립트 수정은 하지 않는다.
- **보고**: 첫 줄 확인 문구, 이어서 쓴 파일 경로와 화면당 한 줄(우회한 것이 있으면 그것만).
