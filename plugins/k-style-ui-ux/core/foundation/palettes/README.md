# 팔레트 라이브러리

하네스를 **빌드할 때** 미리 수집해 둔 국내 서비스 컬러 팔레트. 구동 중에는 이 목록에서 먼저 고르고, 맞는 도메인이 없을 때만 `scripts/palette_scrape.py`로 새로 수집한다.

## 수집 방법

1. `scripts/palette_scrape.py <slug> <url> --name --domain --tags` — CSS 변수의 숫자 단계 스케일(`--blue-500` 등)과 화면 요소의 실사용 색을 수집, 홈 캡처를 `/tmp/hd/palette-shots/`에 저장.
2. **브랜드 색은 사람이(빌드하는 쪽이) 캡처를 보고 확정**해 `--brand`로 넘긴다. 자동 판정(가장 많이 쓰인 유채색)은 할인 빨강·배너 색에 끌려가 절반쯤 틀렸다(마이리얼트립·무신사·클래스101·야놀자).
3. CSS 변수 스케일이 없는 사이트(대부분 — CSS-in-JS·빌드된 Tailwind)는 **측정 색으로 합성**: 회색은 실측 무채색, 브랜드 500단계는 실측 원본 그대로, 옅고 짙은 단계만 계산. 파일에 `"synthesized": true`.
4. **강조색(accent)**: 브랜드와 따로, 그 서비스가 드물게 쓰는 강조색(29CM 할인율 주황처럼)이 있으면 `"accent": {"scale", "step", "seen"}`으로 적는다 — `seen`은 그 서비스가 어디에 쓰는지. 실사용 빈도로 고르는 수집으로는 잡히지 않으니 디자인 시스템 CSS 변수(`accent`·`point`·`highlight` 이름)나 캡처에서 사람이 확인한다. `derive.py`는 이것을 `--c-accent`(점, 3:1)·`--c-accent-text`(글자, 4.5:1)로만 내고 공용 부품은 쓰지 않는다 — 쓰는 법은 `COMPONENTS.md`의 "강조색".
5. **둥글기(shape)**: 라이브러리 팔레트와 브랜드 시드(`seeds.json`) 모두 — 390px 모바일 뷰 홈 화면에서 버튼·카드의 `border-radius` 중앙값(0 제외)을 재서 `"shape": {"r_s", "r_m", "r_l", "seen"}`으로 적는다 — `r_m` 버튼·입력, `r_l` 카드·블록, `r_s` 배지(`r_m`의 절반). 카드의 70% 이상이 0이면(무신사·화해·올리브영) `r_l: 0`. 재지 못한 곳(오늘의집·트리플·직방·이솝)은 넣지 않는다. `derive.py --palette`는 이 값을 쓰고, 없으면 `--shape normal`(8/12/16). 색만 바꾸면 모든 앱이 같은 모양이 된다 — 팔레트를 바꾸면 둥글기도 같이 바뀐다.
6. `derive.py --palette`가 역할 색을 고를 때 팔레트에 중간 회색이 비면(합성 팔레트) 먹색·배경 사이에서 보조(7.5:1)·옅은 글자(4.8:1)를 계산한다.

## 브랜드 시드 거르기 (`scripts/seed_sheet.py`)

- 색이 비슷한 시드는 **도메인이 겹칠 때만** 하나로 합친다 — 전에는 쏘카(모빌리티)·Spotify(음악)·쿠팡이츠(음식)가 비슷한 파랑·초록에 밀려 빠지면서 그 도메인이 통째로 사라졌다.
- **밝은 브랜드(`bright`)**: 흰 글자가 3:1이 안 되고 3:1까지 어둡게 하면 다른 색(ΔE>16)이 되지만 먹색 글자는 4.5:1 이상인 색(카카오·카카오뱅크 노랑, 배민 민트, 치지직·밴드 초록, 밀리 노랑). 버리지 않고 남기며, `derive.py`가 면(버튼·스위치·틴트)은 원색 그대로, 버튼 글자·선(`--c-brand-line`: 선택 테두리·탭 밑줄·진행·별·하트)·링크는 먹색으로 낸다. 시안 4개(어둡게+흰 글자 / 먹색 글자·선 / 짙은 같은 색 / 먹색 브랜드+노랑 강조)를 같은 화면에 입혀 비교해 고른 방식(`docs/pr/bright-brand/`).
- **모노 시드(`mono`)**: Threads·X처럼 검정이 브랜드인 서비스. 탁함·명도·빨강 겹침 거르기에서 빼고, 바탕은 중립 회색으로 만든다.
- 이미 승인된 시드(`seeds.json`)에 손으로 붙인 성격 낱말·도메인·둥글기는 다시 걸러도 보존된다.
- 점수(`palette_pick.py`): 시드는 맞은 도메인 낱말마다 3 — 도메인이 더 정확히 맞는 시드가 성격 낱말 수로 뒤집히지 않게. 시드가 기본값이면 대안은 시드·라이브러리를 한 줄로 세워 점수 순(색상각 40° 이상 차이).

## 타깃 성별 표시(`gender`)

타깃 성별 지향이 근거로 분명한 곳만 `"gender": "여성"|"남성"` + `"gender_source"`(출처·연도)를 적는다 — 서비스 공식 소개가 타깃 성별을 밝혔거나 이용자 조사에서 한 성별이 압도적(약 70% 이상)일 때. 지금: 지그재그·화해(시드), 29CM(라이브러리). 무신사는 남성 54%(2020)라 표시하지 않는다. `palette_pick.py --gender`는 PRD에 타깃 성별이 적혀 있을 때만 넘기고, 일치하면 +1(성격 낱말 하나와 같은 무게 — 도메인 점수를 뒤집지 못한다).
