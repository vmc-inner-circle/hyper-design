## PAGE 1. SERVICE OVERVIEW

### 01. 어떤 서비스인가요?

자연곱슬머리를 펴는 시술 없이 그대로 기르고 관리하려는 사람들이 자신에게 맞는 헤어케어 루틴을 기록하고 발견할 수 있도록 돕는 **모바일 앱**입니다.

사용자는 하루하루

> 어떤 제품을 사용했고 → 어떤 순서와 방법으로 관리했으며 → 그 결과 머리가 어떻게 변했는지

를 사진과 함께 기록합니다.

이 기록이 축적되면서 사용자는 시행착오를 반복하는 대신 **"내 머리에는 어떤 제품과 어떤 루틴이 잘 맞는가"**를 스스로 찾아갈 수 있습니다.

장기적으로는 각 사용자의 기록을 연결하여 비슷한 모발을 가진 사람들의 실제 사례와 루틴을 탐색하고 서로 경험을 공유할 수 있는 **글로벌 자연곱슬 헤어 루틴 플랫폼**으로 발전시키는 것을 목표로 합니다.

### 02. 우리가 해결하고 싶은 문제

자연곱슬머리는 같은 '곱슬머리' 안에서도 모발 특성과 상태가 매우 다양하기 때문에, 특정 제품이나 관리법이 모든 사람에게 동일한 결과를 주지 않습니다.

따라서 자연곱슬을 관리하기 시작한 사람들은 보통

> 제품 탐색 → 여러 관리법 시도 → 결과 비교 → 다시 다른 제품과 방법 시도

과정을 반복합니다.

하지만 현재는 이 시행착오를 체계적으로 기록하거나 과거의 결과와 비교하면서 자신에게 맞는 패턴을 찾기가 어렵습니다.

또한 자연곱슬을 그대로 기르는 것이 익숙하지 않은 사람에게는 **"나와 비슷한 머리를 가진 사람도 시술 없이 이렇게 관리할 수 있다"**는 실제 사례 자체가 중요한 정보이자 사회적 증거가 될 수 있습니다.

이 앱은 개인의 시행착오를 기록 가능한 루틴 데이터로 만들고, 궁극적으로 그 데이터가 다른 사용자의 탐색과 의사결정에도 도움을 주는 구조를 지향합니다.

### 03. 주요 사용자

서비스의 사용자는 크게 세 단계로 나뉩니다.

#### ① Observer — 자연곱슬 관리 입문 전 사용자

곱슬머리를 펴지 않고 자연스럽게 기르고 관리할 수 있다는 사실을 처음 접한 사용자입니다.

다른 사람들의 변화 과정과 실제 사례를 탐색하면서 "나와 비슷한 머리도 이렇게 변화할 수 있구나"라는 확신을 얻고 자연곱슬 관리 시장으로 진입하게 됩니다.

#### ② Explorer — 초보~중급 사용자

이미 자연곱슬을 기르기 시작했지만 어떤 제품과 어떤 관리법이 자신의 머리에 가장 적합한지 아직 찾는 과정에 있습니다.

매일의 루틴과 결과를 기록하고 비교하면서 시행착오를 줄이고 안정적인 개인 헤어 루틴에 정착하는 것이 주요 목적입니다.

#### ③ Contributor — 숙련 사용자

이미 자신만의 헤어 루틴을 어느 정도 가지고 있는 사용자입니다.

자신의 루틴과 변화 과정을 체계적으로 정리하고, 좋은 결과를 다른 사람에게 공유하거나 보여주고 싶어 합니다.

장기적으로는 이 사용자들이 다른 사람에게 정보와 경험을 제공하면서 플랫폼의 핵심 콘텐츠 생산자가 될 수 있습니다.

### 04. 핵심 사용자 경험

서비스가 만들고자 하는 가장 중요한 경험은 다음과 같습니다.

| 단계         | 설명                                                  |
| ------------ | ----------------------------------------------------- |
| **RECORD**   | 제품과 관리 행동, 사진, 메모를 하루의 루틴으로 기록   |
| **REVIEW**   | 과거 기록과 사진을 보며 자신의 변화 과정 확인         |
| **DISCOVER** | 좋은 결과가 있었던 날의 제품·관리방법·패턴 발견       |
| **SHARE**    | 좋았던 루틴이나 변화 과정을 SNS 콘텐츠로 생성 및 공유 |
| **EXPLORE**  | 나와 비슷한 모발을 가진 사람의 변화와 루틴 탐색       |

서비스 초기에는 개인 관리와 기록 경험을 중심으로 시작하고, 사용자 데이터가 충분히 축적되면 탐색과 사용자 간 연결 경험의 비중을 점차 확장하려고 합니다.

## PAGE 2. PRODUCT SCOPE & DESIGN PROJECT

### 05. 주요 기능

현재 고려하고 있는 주요 기능은 아래와 같습니다.

#### Hair Profile

사용자의 모발 특성을 프로필 형태로 기록합니다.

향후에는 이 정보를 기반으로 비슷한 Hair Profile을 가진 사용자와 루틴을 추천하는 기능을 고려하고 있습니다.

#### Product Database & Product Registration

루틴에서 사용되는 헤어제품을 제품 DB 기반으로 관리합니다.

사용자는 제품 라벨을 촬영하여 제품을 등록할 수 있으며, 다음과 같은 흐름을 고려하고 있습니다.

> 라벨 촬영 → 브랜드명/제품명 자동 인식 → 사용자 확인 → 제품 저장

특정 브랜드에 종속되지 않는 독립적인 제품 DB를 구축하는 방향입니다.

#### Daily Hair Routine

사용자가 하루 동안 사용한 **제품 + 관리 행동 + 사용 순서**를 하나의 루틴으로 기록합니다.

예) 샴푸 → 컨디셔너 → 리브인 → 젤 → 드라이

루틴에는 결과 사진과 자유로운 메모도 함께 기록할 수 있습니다.

#### Hair Journey / Timeline

날짜별 루틴과 사진을 축적하여 사용자가 자신의 변화 과정을 시간 순서대로 확인할 수 있습니다.

특히 앱을 처음 사용하는 사용자도 기록을 '오늘부터' 시작할 필요가 없도록, 기존에 촬영해 두었던 사진을 여러 장 한꺼번에 업로드하여 과거 Hair Journey를 구성할 수 있도록 하는 것이 중요합니다.

이를 통해 신규 사용자도 앱 사용 초기부터 자신의 변화 과정을 확인할 수 있으며, 서비스 초기 데이터 부족 문제를 완화하는 데에도 도움이 될 것으로 기대하고 있습니다.

#### Social Content Creation

좋았던 루틴이나 헤어 변화 과정을 SNS에서 쉽게 공유할 수 있는 콘텐츠 형태로 생성할 수 있도록 합니다.

사용자의 기록 자체가 개인 관리 데이터인 동시에 자연스럽게 다른 사용자에게 노출되는 콘텐츠가 되는 구조를 지향합니다.

#### Privacy-first Sharing

초기에는 개인 기록 중심으로 서비스를 사용하도록 하고, 향후 사용자가 자신의 기록을 다른 사용자에게 공개하거나 커뮤니티에서 공유할 수 있도록 확장할 예정입니다.

사진 공개에 대한 심리적인 허들을 낮추기 위해 **얼굴 자동 마스킹 / 배경 매팅** 등의 기능을 기본적으로 고려하고 있습니다.

#### Explore

다른 사용자의 Hair Journey와 루틴을 탐색할 수 있습니다.

특히 향후에는 **"나와 비슷한 모발을 가진 사람"**을 중심으로 콘텐츠를 탐색할 수 있도록 발전시키고자 합니다.

#### Challenge & Reward

사용자가 꾸준히 기록하도록 돕기 위한 챌린지 기능을 첫 출시부터 포함하려고 합니다.

예) 루틴 기록 챌린지 → 참여 및 진행상황 확인 → 조건 달성 → 포인트/쿠폰 보상

보상은 자사몰과 연동되는 구조를 고려하고 있습니다.

#### Community — Future Expansion

향후에는 사용자의 루틴 기록을 기반으로 **질문 / 댓글 / 사용자 간 소통 / 루틴 공유** 등의 커뮤니티 기능을 확장할 계획입니다.

### 06. 서비스의 성장 방향

초기에는 **Personal Management App**으로서 사용자가 자신의 루틴과 Hair Journey를 관리하는 가치를 우선합니다.

사용자와 데이터가 축적된 이후에는

> Personal Management → Discovery → Sharing → Community

순으로 플랫폼 경험을 확장하려고 합니다.

장기적으로는 지역과 관계없이 자연곱슬 사용자의 **Hair Profile × Product × Routine × Result** 데이터를 축적하고 분석하여, 유사한 모발 특성을 가진 사용자에게 참고할 수 있는 **Hair Routine Pattern / Standard Routine**을 제안할 수 있는 서비스로 발전시키는 것을 목표로 하고 있습니다.

### 07. 이번 UI/UX 프로젝트에서 기대하는 역할

현재 PRD와 주요 기능 정의는 어느 정도 진행되어 있습니다.

다만 이미 완성된 화면기획을 전달하고 단순히 UI 디자인만 요청하는 프로젝트는 아닙니다.

서비스의 목적과 기능을 이해한 뒤 사용자 관점에서 기존 기획을 함께 검토하고,

> User Journey
> → 핵심 User Flow
> → Information Architecture
> → 화면구조 및 Wireframe
> → 전체 UI Design
> → Component / Design System
> → 개발 전달용 Figma

까지 함께 만들어가는 형태의 협업을 기대하고 있습니다.

따라서 단순 Visual Designer보다는 UX 구조와 화면구성에도 적극적으로 의견을 제시할 수 있는 **Product Designer** 성격의 협업자를 찾고 있습니다.

개발 대상은 **iOS / Android 모바일 앱**입니다.

### 08. 견적 요청 범위

현재 단계에서는 상세 화면 수나 모든 UX 정책이 확정된 상태는 아니며, 본 소개자료와 기존 PRD를 바탕으로 프로젝트의 예상 범위를 검토한 후

**UI/UX 디자인 전체 예상 견적 및 작업 범위**

를 먼저 확인하고자 합니다.

프로젝트 진행 시 세부 User Flow, 화면 범위 및 우선순위는 디자이너와 함께 협의하여 구체화할 예정입니다.

# 0. User Journey

MVP의 주요 사용자 경험은 사용자가 서비스에 처음 진입해 자신의 모발 정보를 쌓고, 다른 사용자와 경험을 공유하며 지속적으로 기록하는 흐름을 기준으로 구성한다.

### 1. Onboarding — 가입 및 나의 모발 정보 등록

소셜 로그인으로 가입 후 프로필과 온보딩 설문을 작성하고, 현재 Hair Status를 등록한다. 필요한 경우 기존에 가지고 있던 과거 기록을 한 번에 등록하여 서비스 이용을 시작할 수 있다.

`로그인 → 약관 동의 → 닉네임 입력 → 최초 HairStatusSnapShot → 온보딩 Survey → 성별 입력 → 과거 기록 등록(optional) → UserSelectedItem 등록(optional) → 서비스 시작`

### 2. HairStatusSnapshot — 나의 모발 변화 관리하기

현재 HairStatusSnapshot을 기록하고, 새로운 상태를 추가하면서 시간에 따른 모발 변화를 축적한다. 과거에 저장한 HairStatusSnapshot은 시간순으로 확인할 수 있다.

`Hair Status 등록 → 새로운 상태 기록 → Hair History에서 변화 확인(Profile 화면에 공개/노출)`

- 용어: 신규 작성 = **생성**, 기존 항목의 날짜/입력값 정정 = **수정**
- 유스케이스: ① 온보딩 최초 등록 ② 신규 기록 생성 ③ 기존 기록 수정/삭제

### 3. Post — 일상적인 모발 관리 경험 기록하기

평소 모발을 관리한 경험과 그 결과를 `Post`로 기록한다. 관리 과정에서 수행한 CareAction과 사용한 Product를 순서대로 기록할 수 있으며, 사진·만족도·메모를 함께 남긴다. 기록 시점의 습도와 이슬점 등 날씨 정보는 가능한 경우 시스템에서 자동 수집한다. 하루에 여러 개 작성할 수 있으며, 작성된 Post는 Community Feed에 공개된다.

`날씨/이슬점/습도 확인(루틴계획) → Post 작성 → 케어 전 사진 촬영/기록 → CareAction/Product 기록 → 결과사진·만족도·메모 → Post 등록 → Community Feed 노출`

### 3.5. UserSelectedItem — 기록용 제품/행위 퀵버튼 커스텀

신규 기록 화면 상단에 표시될 **제품/행위 퀵버튼 목록**을 편집할 수 있다. 버튼을 클릭하면 해당 항목이 즉시 하단 목록에 추가된다. (참고 서비스: BabyTime)

### 4. HairEvent — 모발의 주요 변화 기록하기

커트, 염색, 탈색, 펌, 매직 등 **모발에 비교적 큰 변화가 발생한 경험**을 `HairEvent`로 기록한다. 이벤트 유형, 미용실, 만족도, 사진 및 날씨 정보를 기록한다. HairEvent로 인해 기장·염색 여부·컬 상태 등 Hair Status가 변경된 경우 해당 변화를 Hair Status와 연결하여 관리할 수 있으며, 기록된 HairEvent는 Community Feed에 공개된다.

`변화계획(미용실예약 등) → HairEvent 작성 시작 → 변화 전 사진촬영 → 커트/염색/펌 등 변화 발생 → 변화 정보 기록 → 필요한 경우 Hair Status 업데이트 → Community Feed 노출`

### 5. Feed — 다른 사용자의 경험 탐색하고 반응하기

Community Feed에서 다른 사용자의 Post와 HairEvent를 탐색한다. 콘텐츠를 통해 작성자의 Hair Status와 관리 경험을 확인하고, 작성자의 Profile에서도 모발 정보와 기록을 살펴볼 수 있다. 마음에 드는 콘텐츠에 좋아요를 남길 수 있고, 부적절한 콘텐츠는 신고할 수 있다.

`Feed 탐색 → 콘텐츠 확인 → 작성자 Profile 확인 / 좋아요 / 신고`

# 2. 내 모발 정보 관리하기

## 2.1 HairStatusSnapshot

HairStatusSnapshot은 특정 시점의 사용자의 모발 상태를 의미한다. 한 명의 User가 여러 HairStatusSnapshot을 가질 수 있다. **기존 정보를 계속 덮어쓰는 것이 아니라 새로운 상태를 기록함으로써 시간에 따른 변화를 확인할 수 있도록 한다. 이 변화 이력은 Profile 화면에 공개되어 다른 사용자와 관리 경험을 공유하는 콘텐츠의 일부로서 역할한다.**

## 2.2 Hair Status 입력 정보

현재 정의된 항목:

- **곱슬 타입**: 범위로 지정 (2A~4C)
  - 도움말: 곱슬에도 유형이 있어요. 내 곱슬과 비슷한 곱슬을 골라보세요. 여러가지 유형이 섞여 있을 수도 있어요.
- **모발 공극률**: 저공성, 중공성, 다공성, 모름
  - 도움말: 공극률이란? 머리카락이 수분을 얼마나 잘 흡수하고 유지하는지를 나타내는 성질이에요. 같은 제품을 써도 곱슬마다 결과가 다른 이유이기도 하지요. 처음부터 알기는 어려워요. 차츰차츰 알아가게 된답니다.
- **모발 굵기**: 보통, 가는모발, 굵은모발
- **두피 타입**: 보통, 건성, 지성, 민감성
- **기장**: 숏컷, 귀밑, 턱선, 쇄골, 가슴, 허리
- **염색모 여부**: 없음, 있음
- **탈색모 여부**: 없음, 있음
- **마지막 매직펌 시기**
  - 도움말: 마지막 스트레이트펌 시술 시기를 입력해주세요
- **탈매직 완료 시기**
  - 도움말: 시술모를 완전히 잘라낸 날을 입력해주세요
  - 탈매직 완료여부를 물어서 '예'인 경우에 입력받음
- **연결펌 여부**: 없음, 있음
  - 도움말: 연결펌이란? 뿌리 쪽에 자라나는 곱슬모발과 자연스럽게 어울리도록 기존의 스트레이트 모발에 컬펌을 적용하는 시술이에요.
- **연결펌 시기**

다음 정보는 일자가 아니라 **연/월 단위**로 저장한다: 마지막 매직펌 시기 / 탈매직 완료 시기 / 연결펌 시기

## 2.3 Hair History

마이페이지에서 사용자가 과거에 입력한 Hair Status를 시간순으로 확인할 수 있다.

예:
- 2026년 1월: 컬 타입 2C / 어깨 길이 / 염색 없음
- 2026년 4월: 컬 타입 3A / 쇄골 길이 / 염색 있음
- 2026년 8월: 컬 타입 3A / 가슴 길이 / 염색 있음

현재 상태만 보여주는 것이 아니라 과거 상태와 현재 상태를 함께 확인할 수 있도록 한다. 예: `컬 타입: 2C → 3A`, `기장: 어깨 → 쇄골`

사용자에게 정기적으로 새로운 Hair Status 입력을 유도하는 기능은 MVP에서 제외한다.

# 3. Post 작성하기

## 기본 정보

1. Post는 사용자가 일상적인 모발 관리 경험을 기록하는 콘텐츠다.
2. 하루에 여러 개 작성할 수 있다.
3. Post는 피드 내 `공개`가 Default이다. **비공개가 불가능하다.**

## 3.1 Post 입력 정보

### 필수

**만족도 1~5 (required)** — 1점 매우 아쉬워요 / 2점 아쉬워요 / 3점 보통이에요 / 4점 만족해요 / 5점 매우 만족해요. 특정 Product나 CareAction이 없어도 만족도를 입력할 수 있다.

**기록 날짜 (required)** — 사용자가 실제 모발을 관리하거나 상태를 확인한 날짜. 기본값 현재 날짜, 과거 날짜 선택 가능, **미래 날짜 선택 불가.** 실제 DB 생성 시각은 별도로 저장한다.

**사진 (required, 최소 1장)** — 여러 장 업로드를 지원할 수 있다. 다음 세부 사항은 디자인/개발 단계에서 정의한다: 최대 업로드 개수 / 순서 변경 / 대표 이미지 정책 / 사진 수정 기능.

### 옵션

**자유 메모 (optional)** — 해당 기록에서 느낀 점이나 평소와 달랐던 점. 예: "오늘은 평소보다 컬이 잘 살아났다", "습도가 높아서 오후부터 부스스함이 심해졌다", "새로운 컬크림을 사용했는데 끝부분이 조금 건조했다". 전체 기록에 대한 메모이며, 특정 CareAction/Product에 대한 내용은 각 항목별 메모를 사용한다.

**CareAction** — 사용자가 해당 기록에서 수행한 모발 관리 행동.
`온보딩과정 또는 UserSelectedItem의 설정버튼 → 운영자가 정의한 목록(=카탈로그)에서 선택(도움말 제공) → UserSelectedItem에 등록 → 기록입력`

예: 핑거 코일링(Finger Coiling) / 핑거 롤링(Finger Rolling) / 거꾸로 스타일링(Upside Down Styling) / 보울 메서드(Bowl Method) / 타올 드라이(Towel Dry) / 디퓨저 드라이(Diffusing) / 자연 건조(Air Dry) / 스크런칭(Scrunching) / 기도손(Praying Hands) / 레이킹(Raking) / 스퀴시 투 컨디쉬(Squish to Condish) / 극세사 플라핑(Micro Plopping) / 브러쉬 스타일링(Brush Styling)

- 한 Post에 여러 CareAction을 추가할 수 있다.
- 동일한 CareAction도 여러 번 추가할 수 있다.
- 사용자가 추가한 순서를 저장해 루틴의 순서를 표현한다.

**Product** —
> 원문 주의: "MVP에서는 Product Catalog를 별도로 구축하지 않는다 / 자연어로 직접 입력한다"로 시작하는 문단 전체가 **취소선 처리**되어 있고, 그 아래 구분선 뒤에 아래 정의가 새로 붙어 있다.

제품은 다음 정보를 가진다.
- 이름(한국어)
- 이름(영어) **(optional)**
- 썸네일 이미지
- 브랜드명
- 카테고리 (shampoo, oil, conditioner, treatment, hair mask, gel, mousse, leave-in conditioner, curl cream, essence, etc)

**PostItem (= CareAction / Product)별 설정** — Post에 등록된 각 CareAction/Product을 PostItem이라고 부른다. 각 PostItem에 개별 메모를 자유롭게 입력할 수 있다(선택).
예: `Diffusing: 약한 바람으로 두피만 20분 디퓨징.` / `Finger Rolling: 앞머리만.` / `아베다 비 컬리: 왼쪽 오른쪽 각각 500원 동전만큼 사용.` / `LRUC Curl Balance Mask: 6분간 도포후 헹구어냄.`
전체 Post 메모와 별도로 저장한다. 추가로 PostItem의 순서를 변경할 수 있다.

**날씨 정보** — 기록 시점의 환경과 모발 상태의 관계를 확인하기 위해 저장한다. 기본적으로 사용자가 직접 입력하기보다 시스템이 자동으로 가져오는 방식을 고려한다.
저장 정보: 이슬점 / 습도 / 날씨(맑음, 흐림, 비, 눈, …) / 날씨 기준 시점
**날씨 정보를 가져오지 못해도 Post 작성은 가능해야 한다.**
- 이슬점: 섭씨(℃) 단위로 저장
- 습도: 상대습도(%)로 저장
- 날씨 기준 시점: 사용자가 선택한 기록 날짜 및 기준 시점을 저장. 과거 기록처럼 정확한 시각을 알 수 없는 경우 날씨 API에서 제공 가능한 기준으로 처리한다.

## 3.2 Post 수정 / 삭제

- 사용자는 본인이 작성한 Post를 수정할 수 있다.
- 삭제 시 Confirm을 제공한다.

# 4. HairEvent 기록하기

HairEvent는 커트/염색/펌 등 모발에 비교적 큰 변화가 발생한 이벤트를 기록하는 콘텐츠다. Community Feed에도 노출될 수 있다.

## 4.1 입력 정보

### 필수
- **이벤트 유형**: 커트 / 염색 / 탈색 / 펌 / 매직 / 기타
- **미용실 이름**: 텍스트 입력
- **만족도**: 1~5
- **이미지**: 여러 장 업로드 가능

### 옵션
- **날씨 정보**: Post와 동일 (이슬점 / 습도 / 날씨 기준 시점)
- **메모**

## 4.2 Hair Status와의 연결

HairEvent는 실제 Hair Status의 변화로 이어질 수 있다. 예: `커트 → 기장 변경`, `염색 → 염색/탈색 상태 변경`, `펌 → 컬 상태 변경`

따라서 HairEvent 작성 시 **변경된 Hair Status 정보도 함께 업데이트할지 정책 확인이 필요하다.** 이 정책은 Hair History와 Journey에도 영향을 준다.

## 4.3 공개 여부

HairEvent 역시 Community Feed 콘텐츠이므로 **100% 공개되는 정보다.**

# 7. Notification

MVP에서는 알림과 관련하여 다음 **2개의 화면**을 제공한다.
1. **Notification Center** — 수신한 알림을 확인하는 화면
2. **Notification Settings** — 알림 수신 여부를 설정하는 화면

## 10.1 Notification Center

수신한 알림을 앱 내에서 확인할 수 있는 화면. 알림은 최신순으로 누적하여 표시한다.

- **알림 표시 정보**: 알림 유형 / 제목 / 내용 / 수신 시점 / 읽음·읽지 않음 상태
- **알림 선택**: 연결 가능한 알림을 선택하면 관련 화면으로 이동. 예: `새로운 좋아요 알림 → 해당 Post`. 연결할 화면이 없는 안내성 알림은 별도 이동 없이 내용만 확인.
- **상태**: 알림이 있는 상태 / 읽지 않은 알림이 있는 상태 / 알림이 없는 Empty 상태
- MVP 제외: 알림 개별 삭제 / 전체 삭제 / 검색 / 유형별 필터

## 10.2 Notification Settings

알림 수신 여부를 설정하는 화면. MVP에서는 알림별 세부 시간이나 조건을 사용자가 직접 설정하는 기능은 제공하지 않는다. 알림 종류별로 `ON / OFF`를 설정한다.

- 알림 종류 확인 부탁드립니다.
  - 기록 관련

  - **지정조건 신규피드 알림**: 조건이 일치하는 사용자의 새 글을 알려준다.
    - HairStatusSnapShot의 CurlType, Porosity, Thickness, ScalpType을 필터조건으로 사용자가 직접 지정
  - Community
  - ~~Challenge~~
  - **기념축하알림**: 탈매직완료일로부터 100일, 마지막 시술일로부터 6개월 등
  - 기타 서비스: CatalogItem 추가 완료안내, 기능 업데이트안내 등

## 10.3 MVP UX/UI 범위

Notification 관련 MVP 디자인 화면은 `Notification Center`, `Notification Settings` 두 개로 한정한다. 개별 알림의 발송 조건 및 자동화 로직은 해당 기능의 정책 또는 개발/운영 영역에서 별도로 정의한다.
