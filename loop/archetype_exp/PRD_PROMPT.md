# 익명 PRD 쓰기 — 실험용(정답을 흘리지 않는다)

입력: 앱 하나의 앱스토어 설명 글(`description.txt`). **이 글만** 읽는다. 스크린샷·웹 검색·기억 속 그 앱의 화면은 쓰지 않는다.

이 서비스를 처음 만드는 회사의 기획자가 디자인 에이전시에 보내는 **기획 브리프**를 한국어로 쓴다(3,000~5,000자).

## 담는 것
1. 서비스 개요 — 누구를 위한 무엇인지, 범위(이번 외주는 사용자용 모바일 앱)
2. 해결하고 싶은 문제 3~5개 — 사용자 입장의 불편
3. 타깃 사용자 2~3명 — 이름·나이·상황, 앱을 여는 순간들(언제·왜)
4. MVP 기능 F1~F8 — 기능마다 무엇을 할 수 있는지, 규칙(조건·제한)
5. 범위 밖 · 논의 중
6. 맨 위에 한 줄: "어떻게 보일지는 에이전시 제안을 받고 싶습니다."

## 하지 않는 것 (스크립트가 검사한다 — 걸리면 다시 쓴다)
- **원본 앱·회사·경쟁 서비스 이름 금지.** 서비스 이름은 새로 짓는다.
- **화면 구조 낱말 금지**: 홈, 메인, 첫 화면, 화면, 탭, 격자, 아이콘, 배너, 캐러셀, 카드, 피드, 목록, 리스트, 레이아웃, 스크롤, 버튼, 위젯, 큐레이션, 대시보드, 타임라인, 썸네일, 그리드, 메뉴, 섹션, 페이지, 상단, 하단, 팝업. 기능은 사용자가 **무엇을 할 수 있는지**로만 쓴다("모아 보기", "고를 수 있다", "확인할 수 있다").
- 어느 기능을 가장 먼저·크게 보여 줄지 정하지 않는다(그건 에이전시가 정한다). 기능 순서는 설명 글에 나온 순서대로.
