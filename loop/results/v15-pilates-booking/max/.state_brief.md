# 상태 화면 빌드 공통 지시 (반드시 따른다)
1. 먼저 `/private/tmp/hd/r15p/work/out/.build_brief.md`(1차 공통 지시 — 원칙·COMPONENTS·배지·링크 규칙)를 읽고 그대로 지킨다. 그리고 `journey.md` 6절(상태 화면 사실)을 읽는다 — 표에 없는 숫자·날짜를 지어내지 않는다. 규칙 원문은 `prd.md` 6장 R번호와 `spec_inventory.json`의 그 rule quote.
2. 상태 화면 `<id>--<state>.html`은 **기본 화면 `<id>.html`을 복사해 바뀐 부분만 고친다**. 제목 위치·블록 묶음·사진은 그대로.
3. 상태와 모순되는 정보는 지운다(예: 시작돼 취소 불가인데 '취소하면 차감' 안내가 남으면 안 됨).
4. 오류 이유는 스크롤 없이 첫 화면에 — 문제 칸 바로 아래나 맨 위. 해결 행동이 주 버튼(하단 CTA 문구를 해결 행동으로 바꾼다). 같은 목적 버튼을 하나 더 붙이지 않는다.
   - error: 같은 요소에서 문제 칸만 바뀜 — `field is-error` + `<p class="field-msg">(경고 선 아이콘 svg)문구</p>`. 입력칸이 아닌 블록이면 그 블록 안 문구를 경고 아이콘 + 오류 문구로.
   - confirm: 기본 화면 위에 바텀시트 `<div class="dim"></div><div class="sheet">…</div>` — 되돌릴 수 없는 행동·중복 경고에만. 위험한 확인 버튼은 브랜드 채움 금지(오류 색 글자: `btn secondary` + `field-msg` 같은 위험색 클래스, components.css에서 danger 계열 클래스를 grep해 사용).
   - empty: 첫 사용 — `<div class="empty">` 안 일러스트 + 한 줄 + 다음 행동 하나.
5. 1차 기본 화면은 고치지 않는다. 단, 기본 화면에서 그 상태로 가는 링크가 꼭 필요하면 그 한 줄만 추가해도 된다.
6. 끝나면 쓴 파일명만 한 줄로 보고.
