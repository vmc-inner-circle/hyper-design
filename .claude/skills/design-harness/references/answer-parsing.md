# 보드 답변 해석과 반영

사용자가 붙여넣는 글은 보드의 **"의견 보내기" → [복사하기]** 가 만든 텍스트다(형식은 계약 §3.4에 고정). 그래도 **사람이 손으로 고쳤을 수 있다.** 줄 단위로 관대하게 읽는다. 모르는 줄은 버리지 말고 `메모`로 취급한다.

## 1. 줄 문법

| 줄 | 뜻 | 반영 |
|---|---|---|
| `시안 b(달력 한 장으로 보기)` | 1턴 시안 보드의 첫 줄: 고른 시안 | SKILL 2턴대로 그 시안으로 전체 화면을 만든다(`concept`, `stage` 삭제, `theme` = 그 시안의 look, `board.locked = ["concept"]`) |
| `시안 c 메모: 달력은 이 안처럼` | 시안마다 적은 말 | 고른 시안의 메모 = 고칠 점. **다른 시안의 메모 = 그 안에서 가져올 요소** — 어느 화면의 무엇인지 해석해 screen-writer의 "시안 메모"에 명령형으로 넣는다(예: "홈의 할 일 목록 자리에 시안 C의 모임 카드 모음(grid-3)"). 해석은 답변 로그에 |
| `테마 cream(따뜻한 크림) · 글자 크게 · 버튼색 terracotta(테라코타)` | 화면 느낌 선택 (괄호 안은 사람용 이름, id만 쓴다) | `screens.json` theme = 테마 id, toggles.type = 보통→normal·크게→large, toggles.swatch = 버튼색 id. 뒤에 `(확정)`이면 이미 잠긴 것 |
| (예전 형식) `테마 B · 글자 크게 · 강조 차분` | 분위기·글자 크기·버튼 색 선택(화면에는 '버튼 색 차분하게/눈에 띄게'로 보이지만 글은 '강조 차분/선명'). `(확정)`이 붙으면 이미 잠긴 것 | `screens.json` theme/toggles. B→"b", 크게→large, 보통→normal, 선명→vivid, 차분→calm |
| `안내 문구: 위치 화면 아래 · 아이콘 없음 · 색 어두운 바탕 · 글자 크게` | 화면 디자인 '안내 문구 모음'에서 고른 안내 문구 모양(추천과 다를 때만 온다) | `screens.json` `toggles.toast` = `{ at: 화면 위→top·화면 아래→bottom, icon: 있음→on·없음→off, tone: 흰 바탕→light·어두운 바탕→dark·상태 색 바탕→color, size: 보통→normal·크게→large }`. 조각은 고치지 않는다(부품 CSS가 `<html data-toast-*>`로 모든 화면에 적용). 확정하면 `board.locked`에 `toast` |
| `화면 <S> · 안내 문구 '<문구>' 바꿔: <메모> [toast:<문구 전체>]` | 화면에 잠깐 뜨는 안내 문구 하나를 고쳐 달라 | 그 화면에서 문구 전체가 같은 곳을 찾아 고친다 — 버튼의 `data-stay="…"`(조각)이면 조각을, `screens.json` 그 화면의 `cases[].show`면 데이터를. '창(팝업)으로'·'입력칸 아래 글자로'는 문구를 그 화면의 확인 창·`.field-error`로 옮기는 재작성. `빼기`면 그 `data-stay`/`cases` 항목을 지운다 |
| `확인: <id>=<옵션 텍스트>` | ask 질문에서 추천과 다른 선택 | 옵션 텍스트를 `board.ask[id].options`와 대조해 인덱스 확정 → 구조 반영 |
| `화면 <S> · <이름표> 바꿔: <메모> [<경로>]` | **화면 디자인에서 사용자가 직접 고른 요소**에 대한 변경 (지금 보드의 기본 의견 형식) | 화면 S의 조각 파일에서 `[경로]`로 요소를 찾는다(§4). 이름표의 따옴표 안 글자로 맞는지 확인. 그 화면을 재작성 대상에 넣고 CHANGES에 경로·이름표를 그대로 넘긴다 |
| `화면 <S> · 아이콘 '<A>' 바꿔: 아이콘 <A> → <B> [<경로>]` | 사용자가 Lucide 목록에서 아이콘을 직접 골랐다 | 경로의 `<svg><use href="#i-A">`를 `#i-B`로 바꾼다. 해석 없이 그대로 — B는 허용 목록 안에서만 고를 수 있게 되어 있다. 같은 의미의 아이콘이 다른 화면에도 있으면 `icons.json` 의미 1:1 규칙에 따라 함께 바꿀지 가정 로그에 남긴다 |
| `화면 <S> · <이름표> 빼기 [<경로>]` | 그 요소 삭제 | 경로의 요소를 조각에서 제거. 그 요소가 흐름의 trigger면 흐름을 다시 잇거나 다른 버튼에 trigger를 옮긴다 |
| `<N> 바꿔: <메모>` / `<N> 바꿔` | 영역 N을 바꿔 달라 | N을 screens.json에서 찾아 화면 특정 → 재작성 대상. 메모 없으면 "다른 구성으로 다시" |
| `<N> 빼기` | 영역 N 삭제 | 영역 제거 + 조각의 `data-region` 블록 제거 + 그 영역을 누르는 flow step 정리 |
| `화면 <N> 빼기` | 화면 N 삭제 | 화면 제거 + flow에서 앞뒤 step 연결 |
| `화면 <N> 메모: …` | 화면 전체에 대한 말 | 그 화면 재작성 대상 + 메모 전달 |
| `추가: …` | 새 화면/기능 | 화면이면 새 항목 생성(pattern·regions 3~6·flow 연결). 기능이면 가장 가까운 화면에 영역 추가 |
| `메모: …` | 전역 | 전역 규칙이면 모든 재작성 대상에 힌트. 화면 지정이 없고 규칙도 아니면 가정 로그 |
| `(나머지는 추천대로)` | 종료 표시 | 무시 |
| 그 외 | 사람이 쓴 자유문 | 번호가 들어 있으면 그 번호의 `바꿔`로, 없으면 `메모`로 |

번호 N은 화면일 수도 영역일 수도 있다. 화면은 100 이하, 영역은 101 이상(예전 실행물은 섞여 있을 수 있다). `screens.json`에서 id로 찾는다. 없는 번호면 가장 가까운 번호를 쓰지 말고 가정 로그에 "번호 N 없음, 무시"로 남긴다.

## 1-1. 위치 경로 읽는 법

`[@start-club > div > button]` = 조각에서 `data-region="start-club"` 요소 → 그 안의 첫 `div` 자식 → 그 안의 `button` 자식. `태그:n`은 같은 태그 형제 중 n번째(1부터), 순번이 없으면 하나뿐이다. `@`가 없으면 `.app` 루트부터. 경로가 조각과 안 맞으면(이미 고쳐진 화면 등) 이름표 글자로 찾고 가정 로그에 남긴다.

## 2. 메모 해석 — 흔한 표현 → 조치

턴이 없으므로 되묻지 않는다. 아래 표의 해석을 적용하고 `brief.md`에 `원문 | 해석 | 반영`으로 남긴다.

| 원문 패턴 | 해석 | 조치 |
|---|---|---|
| "글자 더 크게", "잘 안 보여" | 해당 영역의 위계 상향 | 제목 크기 한 단계↑, `text-lg`/`fw-semibold`, 목록이면 행 높이 큰 변형. 두 번 이상 나오면 `type: large` 전역 |
| "너무 복잡", "빡빡", "많아" | 밀도↓ | 영역 안 항목 수 줄이기(5→3), 보조 정보 숨김, 카드로 묶기 |
| "심심", "허전" | 밀도↑ 또는 시각 요소 | stat/badge/avatar 추가, 빈 카드에 요약 숫자 |
| "위로", "먼저 보이게" | 순서 변경 | 영역을 `.content` 첫 자식으로. 좌우 배치면 왼쪽으로 |
| "옆에", "같이 보이게" | 병렬 배치 | `.grid-2` 또는 `.split`으로 묶기 |
| "빼", "필요 없" | 삭제 | 영역 제거 (= 빼기) |
| "버튼 어디", "뭘 눌러야" | primary 액션 불명 | 그 화면 primary 버튼 1개를 영역 안 우상단 또는 하단 고정으로 |
| "나이 드신 분이 보기엔", "어르신" | 읽기 전용 역할의 가독성 | 그 역할 화면들: large 텍스트, 항목 3개 이하, 단일 열 |
| "확정/후보 구분이 안 돼" | 상태 표시 약함 | badge 색 대비 + 아이콘(`circle-check`/`circle-dashed`) 병기 |
| "표로", "달력으로", "목록으로" | 표현 방식 교체 | table / calendar / list 조각으로 교체 |
| "색이 별로", "칙칙" | 테마 문제 | 3턴에서만 테마 1회 변경 허용. 2턴이면 accent 토글 반대값 |

## 3. 반영 순서

1. 삭제(화면 → 영역) 먼저. flow 정리.
2. 추가 화면 생성 → `ids.js`.
3. 변경 메모를 화면별로 모아 screen-writer에 **원문 그대로 + 메인의 해석 한 줄**을 함께 전달. 에이전트가 원문을 다시 해석하지 않게 해석을 명령형으로 쓴다 ("영역 day-list의 행을 3개로 줄이고 각 행 제목을 text-lg로").
4. 건드리지 않은 화면의 조각 파일은 열지도 않는다.
5. lint → build → 확인 → 사용자.

## 4. screen-writer 재호출 프롬프트 틀 (model: haiku)

haiku는 해석하지 않는다. "할 것"에 **대상 영역 key · 쓸 스니펫 이름 · 바꿀 문구/개수**를 다 적는다.
좋은 예: `할 것: next-up 카드의 제목을 .page-title로 올리고, 시간 줄을 .text-xl .fw-bold로 바꾼다.`
나쁜 예: `할 것: 좀 더 크게.`

```
RUN=runs/<project>
SCREENS=<slug>
MODE=revise
KEEP=<바꾸지 말아야 할 영역 key 목록>
CHANGES=
- [<N> <key>] 원문: "<사용자 원문>" → 할 것: <명령형 해석>
- …
DOMAIN=<1턴과 동일한 더미 데이터 힌트>
기존 runs/<project>/screens/<slug>.html을 읽고 CHANGES만 반영해 같은 경로에 덮어쓴다. KEEP 영역의 마크업은 그대로 둔다.
```
