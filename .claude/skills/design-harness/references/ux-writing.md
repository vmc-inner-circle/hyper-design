# 사용자에게 보이는 말 — 쓰기 규칙

보드와 최종 결과물을 보는 사람은 **비디자이너**다. 화면 이름·흐름 제목·번호 항목·버튼 문구·안내 문장은 전부 이 사람이 읽는다. 이 문서의 규칙은 리허설에서 사용자가 직접 지적한 것들을 모은 것이다. (예시는 중립 예시 '동네 독서 모임' — 모임장이 모임을 만들고 회원이 확인한다) 새 PRD에서도 그대로 지킨다.

원칙 세 줄:
1. **디자인·개발 용어를 쓰지 않는다.** 사용자는 컴포넌트를 모른다.
2. **실제 서비스·디자인 산출물에서 쓰는 말을 쓴다.** 만들어 낸 말("이야기 목록", "한 편 보기")은 어색하다.
3. **뜻을 알 수 없는 표시(색 점·기호)는 글자로 바꾼다.**

## 1. 흐름 제목 (`flow.json` → `flows[].name`)

디자인 산출물의 유저 플로우 이름처럼 **짧은 '~하기' 작업 이름**. 8~16자, 18자를 넘지 않는다(lint).

| 쓰지 않는다 | 쓴다 |
|---|---|
| 처음 모임을 만들어요 (해요체 문장) | 첫 모임 만들기 |
| 모임장이 후보 책을 적고 확정한다 ('~한다'체 + 주어) | 책 고르고 확정하기 |
| 회원이 모임 장소와 시간을 확인해요 | 모임 장소 확인하기 |
| 알림 주기 설정 (명사 나열) | 알림 주기 정하기 |
| 공유 범위·알림 주기 정하기 (가운뎃점) | 공유 범위와 알림 주기 정하기 |

- 누가 하는지는 제목에 넣지 않는다 — 카드의 역할 태그(모임장 / 회원 / 모임장 → 회원)가 보여준다.

## 2. 번호 항목 (`screens.json` → `regions[]`)

번호를 누르면 오른쪽 의견 창에 **그대로** 보이는 글이다.

- `label` = **무엇이 보이는 곳 / 무엇을 하는 곳**. 일상어 명사구.
- `why` = **"이게 뭐냐면"** 한 문장, 해요체.
- `prd` = PRD 근거(내부용, 사용자에게 안 보임).

| 쓰지 않는다 (컴포넌트 이름) | 쓴다 |
|---|---|
| 날짜 선택 스트립 | 날짜 고르기 |
| 편집 서랍 (장소·시간·메모) | 일정 내용 적는 곳 |
| 모임 요약 띠 (D-day·장소·인원) | 모임이 며칠 남았는지 |
| 선택한 일정 상세 패널 | 고른 일정 자세히 보기 |
| 회원에게 보이기 스위치 | 회원에게 보여줄지 말지 |
| 집합 장소·시간 큰 카드 | 어디서 몇 시에 모이는지 |

금지어(lint WARN): 카드 · 띠 · 배너 · 스트립 · 패널 · 서랍 · 드로어 · 모달 · 탭 · 칩 · 배지 · 세그먼트 · 토글 · 스위치 · 리스트 · 타임라인 · 섹션 · 영역 · 위젯 · 컴포넌트.

`why` 예: "끄면 회원에게는 '정하는 중'으로만 보여요" · "여기서 첫 모임을 만들어요" · "장소·시간처럼 그대로인 것을 알려줘 안심시켜요".

## 3. 화면 이름 (`screens[].name`)

- 화면에 들어가면 보이는 제목 그대로(예: "모임 홈", "책 고르기", "출석 확인").
- 같은 기능을 역할별로 따로 만든 화면은 뒤에 괄호로 역할: "일정 흐름 (부모)".
- 빈 상태·첫 진입 변형은 뒤에 "(처음)": "모임 홈 (처음)", "이번 모임 (회원, 처음)".

## 4. 단계 문장 (`flow.json` → `steps[].action`)

- **버튼 문구를 그대로 따옴표 안에**: "'변경 3건 보내기'를 누르면", "'주 1번'을 고르면".
- 누르는 사람이 바뀌면 앞에 주어: "회원이 '일정에서 보기'를 누르면".
- "탭", "버튼" 같은 말을 붙이지 않는다: "'11/14 토'를 누르면" (O) / "'11/14 토' 탭을 누르면" (X).

## 5. 사람 부르기

- 윗세대·고객처럼 **높여 불러야 하는 사람**은 "님"을 붙이고 조사 "께"를 쓴다(예: 부모 → 부모님께, 고객 → 고객님께). 역할 라벨 내부 값이 짧아도 화면에 보일 때는 높임말로.
- 역할 태그는 PRD의 역할 이름을 짧게(예: 모임장 / 회원 / 모두). 역할이 바뀌는 흐름은 "모임장 → 회원".

## 6. 보드 화면의 고정 문구 (canvas가 쓰는 말 — 바꾸지 않는다)

| 쓰지 않는다 | 쓴다 |
|---|---|
| 시나리오 / 이야기 / 이야기 목록 | 흐름 / **전체 흐름** |
| 한 편 보기 · n번 이야기 | **따라가 보기** · **흐름 n** |
| 답변 복사 · 의견 보내기 (n) | **의견 보내기 · n개** — 누르면 "이렇게 전달돼요" 확인 창, 마우스를 올리면 개수의 뜻 |
| (아이콘 교체 영역) | **다른 아이콘으로 바꾸기 · 지금: luggage (원래 plane)** · 검색칸 "아이콘 찾기" |
| 배지 | **번호** |
| 패널 · 피드백 패널 | **의견 창** · **의견 남기기** |
| 영역 n | **이 화면의 번호 n개** |
| 확인할 것 / 더 필요한 것 / 지금까지 표시한 것 | 몇 가지만 골라 주세요 / 더 있었으면 하는 것 / 지금까지 남긴 의견 |
| 테마 / 글자 / 강조 · 강조색 · 차분/선명 · 버튼 색 차분하게/눈에 띄게 | 상단 **화면 느낌** 버튼 하나 → 창 안에 **분위기**(PRD마다 만든 이름 3개, 예: 깔끔한 흰색 · 따뜻한 크림 · 밤 바다) · **글자 크기** 보통/크게 · **버튼 색**(색 이름 5개, 예: 바다 파랑 · 청록 · 노을 주황 · 숲 초록 · 먹색) |
| 테마 A · B · C | 분위기 이름 (영어·기호·'테마' 금지) |
| 1차 보드 | 초안 1 |
| 확정: 테마 A · 글자 크게 · 강조 차분 (잠긴 뒤 상단 표시) | 확정: 분위기 깔끔한 흰색 · 글자 크기 크게 · 버튼 색 바다 파랑 |
| 흐름도 / 화면별 의견 | 탭 **사용 흐름** / **화면 디자인** |
| (미리 정한 빨간 번호) | 화면을 직접 눌러 **고른 곳** → 의견 **핀** 번호 |
| 요소 종류 이름 (div·span·svg…) | 버튼 · 입력칸 · 선택 항목 · 메뉴 · 링크 · 이미지 · 제목 · 표시 · 사람 표시 · 메뉴 묶음 · 맨 위 줄 · 목록 한 줄 · 글자 · 부분 · 화면 전체 |
| (의견 창 섹션) | 고른 곳 · 이 화면에 남긴 의견 · 이 화면이 나오는 흐름 · 더 넓게 고르기 |
| (초록 점) | **추천** 글자 |

## 7. 문장 부호

- 제목·이름에 괄호를 겹쳐 쓰지 않는다: "77번 새 모임 만들기 (모임 홈 (처음))" (X) → "'모임 홈 (처음)' 화면의 77번 새 모임 만들기" (O).
- 흐름 제목에는 가운뎃점·괄호를 쓰지 않는다. 화면 속 더미 데이터(예: "하카타 그린호텔 · 1·3박")에는 써도 된다.
