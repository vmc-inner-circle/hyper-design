# oss-design-harness v1

PRD → 질문 1회(무드 고르기) → 병렬 빌드 → 캔버스. 사용자는 디자인을 모른다고 가정한다.

## 불변 원칙

1. **사용자에게는 렌더링된 시안을 보여주고 고르게만 한다.** 전문 용어(타이포, 레이아웃, 위계, 그리드, 톤앤매너, 컴포넌트, IA, UX, UI, 플로우, 와이어프레임, 팔레트, 폰트명) 금지. 답은 글자 하나(`A`)로 끝나게.
2. **화면 구성·흐름은 묻지 않고 스스로 정한다.** 정한 것은 `out/brief.md` 가정 로그에 남긴다.
3. **이해가 먼저, 예쁨은 나중.** 화면마다 핵심 메시지 한 문장 + 주요 행동 1개. 설명 문구로 이해시키는 UI는 실패다.
4. **덜어낸다.** 모든 섹션은 "누구를 위해, 언제 보는가"를 가져야 하고, 없으면 지운다. 같은 목적의 버튼을 두 번 두지 않는다. 데이터가 빈약한 통계·인사이트 칸, 장식용 이모지·일러스트 금지.
5. **뻔한 게 이긴다.** 토스·당근 수준의 국내 대중 앱 패턴. 독창적 레이아웃 금지. 한 화면에 한 가지 일.
6. **절제된 비주얼.** 흑백·회색 기반 + 포인트 컬러 1개(최대 2개). 회색 단계 ≤ 6. 폰트 크기 ≤ 7종, 굵기 ≤ 3종, 패밀리 1종(Pretendard, CDN). 여백은 4의 배수. radius ≤ 4종, 그림자 ≤ 3종. 선택 상태는 모양 그대로 색만 바뀐다.
7. **AI 티 금지.** 모든 것을 둥근 카드로 감싸지 않는다(목록은 구분선, 카드는 정말 묶음일 때만). 카드 안에 카드 금지. 그라데이션·이모지 아이콘·텍스트 그라데이션 금지. 아이콘은 인라인 SVG(선 1.75px, 24px) 또는 텍스트 라벨.

## 진행 (턴 구조)

사용자 턴은 최대 4번(PRD 포함). 이 하네스는 **2번**만 쓴다: ① PRD 입력 ② 무드 선택 답.

### 턴 1 — PRD를 받으면 (목표 4분)

1. 첫 줄에 안내: "질문은 딱 1번 드립니다. 고르신 뒤 약 10분 동안 알아서 만듭니다."
2. `out/brief.md` 작성 (직접, 빠르게):
   - 역할: 만드는 사람 / 보기만 하는 사람 등 PRD에서 읽히는 역할과 각자의 화면 차이
   - **화면 인벤토리 12~14개**: id(영문 kebab) · 제목 · role(`planner`/`viewer`/`shared`) · 핵심 메시지 한 문장 · 주요 행동 1개 · 섹션 목록(각 섹션의 대상·시점) · traits · 연결 화면
   - PRD 커버리지: 기능 요구사항(F1..)·유저스토리(US1..)마다 담당 화면 id
   - 가정 로그
   - 상태 파생(아래 규칙)
3. 무드 시안 3개를 **서브에이전트 3개로 병렬** 생성(Agent 도구, 한 메시지에 3개). 모두 **같은 화면**(보기만 하는 사람의 홈, 없으면 메인 홈)을 같은 콘텐츠로 만들되 무드만 다르게:
   - A: 차분·신뢰 (따뜻한 흰 배경, 짙은 남색/청록 포인트, 넉넉한 여백)
   - B: 밝고 친근 (흰 배경, 선명한 주황/코랄 포인트, 중간 밀도)
   - C: 단정·정보형 (연회색 배경, 파랑 포인트, 촘촘하되 정돈)
   각 에이전트는 `out/ask/mood-X.html`(375px 폰 화면 1장, 자체 `<style>`에 CSS 변수로 토큰 선언)을 쓴다. 불변 원칙 전부를 프롬프트에 붙여 넣는다.
4. `python3 .claude/skills/oss-design-harness/scripts/ask_page.py out/ask` 실행 → `out/ask/index.html`(세 시안을 나란히, 큰 A/B/C 라벨).
5. 답변 마지막 줄을 정확히 이 형식으로 끝낸다:
   `[[ASK out/ask/index.html]] 세 가지 화면 중 이 앱에 가장 어울리는 느낌을 골라주세요. (A / B / C)`

### 턴 2 — 답을 받으면 (목표 8분)

1. 고른 시안의 CSS 변수를 그대로 가져와 `out/tokens.css`(토큰 + 공통 클래스: 앱바, 버튼 primary/secondary/text, 목록행, 섹션 제목, 칩, 입력, 탭바, 바텀시트, 스켈레톤)를 쓴다. 시안에 없던 값은 원칙 6 안에서 정한다.
2. `out/screens.json` 매니페스트 작성 (스키마 아래).
3. 화면 빌드: 서브에이전트 **4개 병렬**(한 메시지에), 화면을 3~4개씩 나눠 맡긴다. 각 에이전트에 전달: 불변 원칙 전문, `out/brief.md`, `out/tokens.css` 경로, 맡은 화면 목록(id·제목·role·핵심 메시지·주요 행동·섹션·links·states), 화면 규칙:
   - 파일: `out/screens/<id>.html`, 상태 변형은 `out/screens/<id>--<state>.html`
   - `<link rel="stylesheet" href="../tokens.css">` 사용, 화면 전용 스타일은 최소한. 새 색·새 폰트 크기 금지.
   - `<h1>`은 정확히 1개(앱바 제목 또는 화면 제목). 채워진 포인트 컬러 버튼은 화면당 최대 1개.
   - 터치 영역 44px 이상. 본문 15px 이상, `viewer` 화면 본문 17px 이상. 최소 글자 12px.
   - 이동하는 요소는 `<a href="<id>.html">`로 실제 연결(links의 화면으로). 탭바도 링크.
   - 더미 데이터는 PRD 맥락의 현실적인 한국어(실제 이름·지명·날짜·시간). "텍스트", "제목", lorem, TODO, "여행 1" 금지. 이미지가 필요하면 단색 블록+라벨이나 SVG로, 외부 이미지 URL 금지.
   - `title` 속성, 물음표 도움말 아이콘, 툴팁 금지.
   - 375px 폭에서 가로 스크롤이 생기면 안 된다.
4. 모든 에이전트가 끝나면 `python3 .claude/skills/oss-design-harness/scripts/build_canvas.py out` 실행 → `out/index.html` 캔버스.
5. `python3 .claude/skills/oss-design-harness/scripts/selfcheck.py out` 실행. 실패 항목이 있으면 해당 파일만 직접 고치고 한 번 더 실행(최대 1회).
6. 마지막 줄: `[[DONE out/index.html]]`

## 상태 파생 규칙 (넘침도 실패)

상태는 traits에서만 나온다. 규칙에 안 걸리면 default 하나가 정답이다.
- `empty` ← `list_first_use`: 목록 화면이고 처음 쓰는 사람이 빈 목록을 보게 됨. 빈 상태는 다음 행동 1개를 제시한다.
- `error` ← `form`: 입력 폼 화면. 인라인 검증 메시지.
- `disabled` ← `readonly_role`: 같은 화면을 보기만 하는 역할이 봄(편집 요소가 비활성/숨김).
- `loading`·`success`·`initial` 금지. 짧은 대기는 스켈레톤 클래스, 긴 작업·완료는 별도 화면.
- 화면당 default 포함 최대 3개.

## screens.json 스키마

```json
{"screens":[{"id":"home","file":"screens/home.html","title":"홈","role":"viewer",
  "purpose":"핵심 메시지 한 문장","primary_action":"..",
  "sections":[{"name":"..","audience":"..","when":".."}],
  "traits":{"list_first_use":false,"form":false,"readonly_role":false},
  "states":[],"links":["detail"],"group":"부모 화면"}],
 "prd_coverage":{"F1":["..."],"US1":["..."]}}
```
`group`은 캔버스에서 한 줄로 묶일 흐름 이름(예: "계획 만들기", "부모가 보는 화면"). `links`가 캔버스 화살표가 된다.
