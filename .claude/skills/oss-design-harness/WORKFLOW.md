> 사용자 요청(09-28): "중간중간 묻지 말고 한 번에 다 물은 다음, 사용자는 그냥 20~30분 기다리도록(다른 일을 할 수 있도록)."
> 질문은 **딱 1번**(질문 페이지 1장). 그 뒤로는 끝까지 묻지 않는다 — 원래 질문 2~4 에서 하던 확인(개선안·재검증)은 하네스가 스스로 판단해 적용하고 `design/decisions.md` 에 남긴다.
> 엔진 SKILL.md 의 "질문 4번" 은 이 카드에서는 "질문 1번" 으로 읽는다. 한 페이지 items 3개 제한도 이 카드에서는 **5개까지**.

## 시작 (PRD 를 받은 턴) — 목표 8분, 길어도 10분

사용자는 PRD 를 넣고 바로 이 페이지를 받는다. **이 한 페이지에 모든 결정이 들어가야 한다.** 그러니 공통 작업을 먼저 끝내고, 답에 따라 갈리는 것만 묻는다.

1. `design/brief.md`: 핵심 갈등 한 문장, 역할, 기기 가정, 기능 F목록, 필수 흐름, 가정, **전체 화면 목록**(이름·역할·목적·features). 내용 데이터(사람 이름·장소·날짜)도 여기서 정한다.
2. `design/app/base.json` 초안(order 에 화면 목록 전부) — 답을 받으면 바로 에이전트를 띄울 수 있게.
3. 후보 그림(`design/cand/`, 화면 JSON → `app.py --out` → `shots.py cand design/cand --d`). **서브 에이전트 없이 메인이 짧게**:
   - **방향 3안**: 핵심 갈등을 다르게 푸는 대표 홈 화면(역할 = 주 사용자) 3개. **형태가 서로 달라야 한다** — 폰 내비(`nav`)·배치(`layout`)·주인공 블록 중 둘 이상이 다르게(SKILL '이 서비스만의 얼굴' 표). 각 안 `desc` 에 "이 사람이 이 순간에 이렇게 쓰니까" 한 줄.
   - **개성 4안**(분위기): 스타일 라이브러리(`python scripts/styles.py list`)에서 **성격표가 모두 다른 4개**(요즘 유행 1 · 오래 가는 1 · 과감한 1 · 따뜻한 1)를 이 PRD 사용자 상황에 맞게 골라, 추천 방향의 홈 화면 JSON 하나로 `python scripts/styles.py try design/cand/<홈>.json <id1> <id2> <id3> <id4>` → `design/cand/style-<id>.png`·`-d.png`. 첫째 = 하네스 추천. 선택지 `label` = "<스타일 이름> · <성격표>", `desc` = 이 서비스에서 왜 어울리는지 한 줄 + 시그니처 디테일. 스타일마다 palette 0/1 중 이 서비스에 맞는 쪽(`--palette 1`).
     **다섯째 = "알아서 해 주세요 · 완전 자유"** (사용자 09-28: "모델한테 네가 생각하는 앱을 만들어라 — 완전 자유도"): 라이브러리를 쓰지 않고 **이 모델이 스스로** 이 PRD 에 가장 와우라고 생각하는 컨셉·은유·색·도형·글꼴로 같은 홈 화면을 `design/cand/free.html`(HTML 직접 + `free.css`, 화면 JSON 에 `htmlFile`·`styleFile`) 로 그린다 → `shots.py cand` 로 캡처. 서브 에이전트 1개에 맡겨 다른 후보와 동시에 만든다(지시: "라이브러리·예시를 보지 말고, 이 PRD 사용자의 상황에서 네가 가장 멋지다고 생각하는 홈 화면"). `desc` = 모델이 정한 컨셉 한 줄.
   - **보는 사람 첫 화면 2안**(PRD 에 확인만 하는 사람·초대받는 사람이 있으면): 그 역할의 첫 화면 2개.
4. `design/ask/q1.json` — items (이 순서, 5개 이하):
   - a = pick 방향 3안(추천 표시, why 에 이유)
   - b = pick 개성 5안(라이브러리 4 + 완전 자유 1)
   - c = pick 보는 사람 첫 화면 2안 (없으면 생략)
   - d = assume 가정 4~6개(수량·기기·함께 쓰는 방식 등, 틀린 것만 누름)
   - e = check "완성하면서 이렇게 하려고 해요"(하네스가 이 PRD 사정에서 미리 정한 품질 방침 3~4개). 기본 전부 적용, 빼고 싶은 것만.
   - `lead` 첫 문장: "이 페이지 하나만 답해 주시면 끝까지 만들어요. 답을 보내고 20~30분 뒤에 완성본을 보여 드릴게요 — 그동안 다른 일 하셔도 돼요."
   - 페이지 맨 아래 '말로 적기' 칸은 ask.py 가 자동으로 붙인다(메모는 선택보다 우선).
5. `[질문 1] design/ask/q1.html`

## 답을 받은 턴 — 끝까지 한 번에 (목표 22분, 길어도 27분). 다시 묻지 않는다.

1. `ask.py --read` 로 풀어 `design/decisions.md` 에 원문·풀이. 메모가 있으면 메모 우선.
2. **개성 먼저 (메인, 5분)**: "완전 자유" 를 골랐으면 `free.css` 를 `design/app/style.css` 로 키우고(80~200줄) 라이브러리 없이 진행, 대표 화면은 3~5장 직접 그린다. 아니면 고른 스타일 → `cp styles/<id>.css design/app/style.css` + `styles.py use <id>` tokens 를 base.json 에 → 이 서비스의 은유·시그니처 디테일 2~3개를 style.css 에 **덧붙임**(메모가 있으면 반영) → `brief.md` 에 확정 → 역할별 대표 화면 2~4장을 `screens/<id>.html` 로 직접(SKILL '디테일로 와우').
3. 나머지 화면은 **서브 에이전트 동시 생성**(SKILL '전체 화면을 만드는 법'). 지시문에 은유·시그니처 디테일·`style.css` 의 클래스 이름과 `cls` 쓰는 법을 붙인다 — 블록 화면도 같은 개성으로.
4. `app.py design/app` → `coverage.py` PASS → `shots.py app` → **비평 한 바퀴**(SKILL '디테일로 와우' 6) → **눈으로 검사**. 이때 원래 질문 2~4 에서 사용자에게 물었을 것들을 스스로 확인하고 고친다:
   - 고른 분위기가 실제 전 화면에서 어색하지 않은지(작은 폰·큰 글자 기준 재검증 포함)
   - 탭 아이콘이 서로 겹치지 않는지, 한 화면에 같은 제목·같은 요약이 두 번 나오지 않는지, 빈 그림·빈 아이콘이 없는지
   - 스스로 찾은 개선안은 **적용하고** `decisions.md` 에 "하네스가 스스로 고친 것" 목록으로 남긴다(사용자에게 묻지 않음).
5. `base.json` 의 `decisions` 에 q1 의 답과 반영 화면, `tour` 8~12단계.
6. 마지막 줄 `[완료] design/app/index.html`. 완료 메시지 본문에 "고른 것 → 반영된 곳" 3~5줄과 "스스로 고친 것" 3줄 이내.
